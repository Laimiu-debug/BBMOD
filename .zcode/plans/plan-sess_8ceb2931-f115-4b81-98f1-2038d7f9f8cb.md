# BBMOD 管理器 — 实施方案 v2（含自研汉化管线 + 通用 mod 诊断）

Python 3.12 + PySide6 桌面应用（中文 UI），放 `G:\code\BBMOD\app\`，绑定游戏 1.5.2.3，PyInstaller 打包。

## 一、MOD 管理（不变）

扫描游戏 data/（区分官方 `data_NNN.dat` 与用户 zip）；内置合集仓库 + 外部文件夹导入；安装=复制进 data/，禁用=移出到 `游戏根目录\bbmod_disabled\`；挂载顺序视图、profile 保存/切换、EIMO 双层 zip 自动解出。官方 .dat 档案**只读不写**。

## 二、一键汉化 v2 —— 自研汉化包生成管线（新增核心）

不再分发狐狸汉化 zip，而是**读取游戏文件 + 参考语料，生成我们自己的汉化包**：

- **语料层**：解析狐狸汉化 zip 中 2626 个明文 .nut 脚本，用正则抽取全部字符串字段（`m.Name/m.Description/m.Title` 等）建立**翻译数据库**（SQLite：文件路径+字段+中文串）；同时用 Python zipfile 直接读取游戏 `data_001.dat`（已确认是无加密 ZIP）提取 UI 明文 .js/.css/字体作为补充语料
- **覆盖层**：`overrides.json` —— 我们自己的修改/润色条目，优先级高于语料
- **资源层**：自选中文字体（可换掉狐狸的 main.ttf）+ fonts.css 重定向 + 汉化技能图标（沿用参考包资源）
- **构建器 `l10n_builder.py`**：语料 + 覆盖 → 重写脚本字符串 → 连同字体/图标/hooks 打包为 `BBMOD汉化_YYYYMMDD.zip`（自有品牌，可重复构建）
- **翻译表编辑器 UI 页**：搜索/浏览全部字符串、即时修改（写入 overrides）、预览、一键重建汉化包 → 安装
- **基座检测**：检测 `data_001.dat` 是否为汉化重打包版（条目时间戳全为 2026 即是，你本机现在就是这种状态）——是则提示"游戏基座已非原版，建议 Steam 校验还原后使用本软件汉化"，并标注对刷种子的影响
- **远期（标记为 stretch）**：cnut 反编译或社区原版 dump 获取英文原文，做英中对照翻译记忆库

## 三、刷种子（不变：全自动编排 + 实时结果）

配置 UI（5 种预设模式 + 人物六种条件/地图 31 项指标/红装 4 模式表单化编辑）→ 生成 4 个 config_*.nut → 快照 mod 状态 → 净化（移出全部 mod）→ 注入 payload（mod_hooks + scripts + seed_generator，.nut 原样分发：RNG 模拟核心必须留在游戏引擎内，评分公式/条件判定/配置生成/log.html 解析全部用 Python 重写）→ 启动游戏（用户在游戏内点一次"开始新战役"）→ 实时解析 log.html（OneDrive Documents 路径探测、单行 HTML 按行切分）结果表格增量刷新 → 一键停止（taskkill）→ 清理 → 恢复原 mod 状态。**新增前置检查：基座纯净检测**（data_001.dat 为汉化重打包版时警告 RNG 可能失真，建议先 Steam 校验）。

## 四、诊断引擎 v2 —— 对任意第三方 mod 生效（不依赖合集元数据）

所有规则基于**zip 静态分析**即可运行，内置已知-mod 表只是增强层（友好名称/已知互斥）：

- **静态分析器 modinfo.py（对任意 zip）**：遍历 zip 条目 → 找 `scripts/!mods_preload/` 入口 → .nut 明文正则提取 `::mods_registerMod` / `::Hooks.register` / `require/conflictWith/queue(">x")` → 判定 API 代际（旧 mod_hooks v21.1 / 新 Modern Hooks）；.cnut 编译入口标记"无法静态分析"并用**遮蔽路径启发式**推断影响面
- **冲突识别**：依赖缺失（如需 MSU 未装）、API 代际不匹配（新 API mod 无 Modern Hooks）、**任意两个已启用 zip 的同路径文件覆盖冲突**（按挂载顺序报"后者覆盖前者"）、preload on_start/on_running 清单冲突（提供自动并集合并）、互斥规则（内置表 + 自定义规则入口）
- **版本检测**：游戏 exe 版本 vs 1.5.2.3、mod 版本格式预检（mod_hooks v21.1 拒绝非纯数字版本——本机 swifter"1.1.3"就是实例）、DLC 完整性（种子生成器需全 DLC）、data_001.dat 基座完整性
- **影响地图/RNG 检测**：按 zip 遮蔽的文件路径分类——触碰 `scripts/config/world.nut`、`scenarios/`、`entity/tactical/player*`、`skills/traits/`、`items/`、红装 randomize 的标记"影响种子生成"；纯 gfx/ui/sounds 标记"安全"；用于诊断报告 + 刷种子净化依据
- **运行时诊断（新增，静态分析的兜底）**：解析最近一次游戏会话的 log.html——把 `Script Error`、mod 注册成功/失败行（如 swifter 的版本号报错、职业属性的 `'Hooks' does not exist`）、`Unexpected file` 警告关联到已装 zip，呈现"上次启动实际结果"——**即使 cnut 编译 mod 也能确诊**
- 仪表盘页：游戏状态 + 已装 mod 健康列表（绿/黄/红 + 原因 + 修复建议），你本机现有 6 个 mod（含 2 个坏的）是现成验收样本

## 五、测试计划（基于本机真实环境）

单元：modinfo 分析器全量跑本机 6 个已装 zip + 合集 50 个 zip；log_watcher 用现有 log.html fixture；config_emitter 快照测试；评分移植对拍；**l10n_builder 用狐狸 zip 全量跑通构建并抽验字符串替换正确性**。
真机：Steam 检测链、诊断引擎（必须准确报出本机 2 个坏 mod + 基座已汉化事实）、安装/禁用/恢复幂等性、刷种子端到端（需你在游戏里点一次"开始新战役"）、基座检测对当前汉化重打包版正确告警。
安全红线：只动快照记录在案的文件；官方 .dat 永不写入；操作日志留痕；恢复幂等。

## 六、里程碑

M4 自研汉化管线（语料抽取 → 翻译表编辑器 → 构建器 → 一键安装/卸载）
