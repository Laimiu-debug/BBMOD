# BBMOD · 战团整备所

面向《战场兄弟》1.5.2.3 的本地桌面工具：营地诊断、MOD 军械库、汉化管理、种子远征、装备百科与反馈。

## 下载测试版

[网站下载](https://bbmod.site/downloads/)提供 `BBMOD-0.3.0-rc.24.exe`，配套[独立汉化包](https://bbmod.site/mods/22c174ed-fc9d-4dbb-9642-44831ce694e8/)为 `0.3.0-rc.7`。本版包含离线装备表格与图标、红装鉴定修复、启动和汉化状态引导、种子批量分享及快捷复制，详见 [rc24 说明](releases/0.3.0-rc.24.md)。

本轮通读 15,819 条中文文本及随机分支，修订 634 条，统一术语，改善剧情措辞与动态拼接，补齐南方人物称呼顺序并修正原版几处文字排版错误。程序文件为 `dist/BBMOD-0.3.0-rc.24.exe`，现成汉化包为 `dist/mod_bbmod_zhcn-0.3.0-rc.7.zip`；可直接导入并应用，已启用新版包时无需生成。

当前源码中的「装备百科」默认打开「装备表格」：可离线查阅 491 个武器、身体护甲、头盔和盾牌条目，包含 94 种红装；支持中英文搜索、类型与品质组合筛选、点击表头排序、双击查看属性详情。436 个条目展示原版图标，其余特殊条目说明原版没有物品图标。查表不需要游戏目录或读取 MOD。普通和传奇装备显示基础值，红装显示抽中词条后的随机范围；详情保留未强化数值与两词条规则，特殊条目说明获取限制。

「装备鉴定」是同一页面的第二个页签，在这里安装或更新读取 MOD，重启游戏，保持 BBMOD 运行即可悬停查看。装备对比使用独立小框，保留游戏原属性框全部内容并自动避让。Ctrl+Alt+D 默认暂停 / 恢复，可直接录入其他快捷键；背景不透明度可调。鉴定结果可以定位到装备表格；后台读取不打断查表。实际游戏悬停与第三方 MOD 组合仍需玩家验收。细节见 [桌面工具说明](docs/desktop-tools.md)。

## 字体与字号

点击左侧最下方「设置」或按 **Alt+7**，选择本机可用的中文字体及 **10–18 号**文字，查看预览后点击「应用字体」。全软件即时生效，重启后保留；「恢复推荐」可重新预览内置 Noto Sans SC 与 12 号文字，再点击应用保存。

默认正文从 13 像素增大到 12 号（约 16 像素），提示文字、表格行高、表头列宽和标题区域同步调整。较大字号或较小窗口下可滚动查看内容。缺失的系统字体自动回退到内置中文字体。这些设置仅影响 BBMOD 管理器，游戏内文字继续由汉化包提供。

验证：`python tools/check_font_settings_ui.py` 使用隔离配置及隐藏的 Windows Qt 窗口，检查预览、键盘操作、即时应用、真正重启后的保留、字体缺失回退、写入失败恢复与 28 组页面布局；不启动游戏。配置位于 `%APPDATA%/BBMOD/settings.json` 的 `appearance` 项。

## 在线军械库

进入「MOD 军械库 → 在线军械库」，填入站长提供的网站根地址并连接。支持搜索作者作品、查看说明、下载校验并安装；更新时备份旧版，保留启用/禁用状态，可恢复上一版。未受管理或已手动修改的同名 ZIP 不会被覆盖。前置与冲突按 MOD ID 检查，版本范围和 DLC 要求需阅读作者说明。网站部署见 [web/README.md](../web/README.md)。

## 版本管理与自动更新

进入「设置」可手动检查更新、查看进度和调整自动更新；右上角「版本与更新」保留历史版本入口。优先读取官网版本，失败时使用 GitHub。rc.13 及更早版本仍使用旧 GitHub 源，需要从网站下载 rc.14 一次，之后可通过官网更新。

- 默认开启启动后后台检查；距离上次成功检查不足 6 小时则复用版本记录，软件持续运行时每 6 小时检查一次，也可随时点击「立即检查」。可以关闭自动检查。
- 支持「稳定版」与「稳定版 + 测试版」通道。本版为测试版，默认包含测试版；稳定版通道没有发行版时会明确提示，不会把测试版误报为稳定版。
- 发现较新版本后，右上角显示提示。检查失败、断网或 GitHub 限流不会阻塞主界面，也不会被显示成“已经最新”。
- 选择版本可阅读说明、打开发布页面或下载 EXE。下载支持取消，并校验发布资产的大小、SHA-256 和 Windows 程序标识；校验失败不允许安装。
- 默认在后台下载并校验新版，正常退出后静默替换，不重新打开程序。也可主动点击「立即重启更新」。替换失败会尝试恢复旧版，程序旁保留旧 EXE 备份；自动检查、自动下载、退出安装可分别关闭。
- 正在刷种子、构建汉化或处理 MOD 时禁止重启更新。设置和下载记录存于 `%APPDATA%/BBMOD`，汉化与 MOD 配置不随 EXE 替换。已有汉化 ZIP 不会被自动重新生成。
- 历史版本可以下载留存；软件不会自动降级。源码运行时可检查和下载，安装按钮仅在 Windows 打包版中启用。无目录写权限时可打开下载目录手动处理。

更新检查使用官网 `/api/v1/desktop/releases/`，并兼容 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases)，不需要登录。发布说明按纯文本展示。重启使用 [PyInstaller 的独立进程环境](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#using-sys-executable-to-spawn-subprocesses-that-outlive-the-application-process-implementing-application-restart)，避免继承已退出程序的解包目录。

开发检查：`python -m pytest tests/test_app_updates.py tests/test_update_network.py`；`python tools/check_updates.py --download` 会在临时配置中检查公开版本并下载校验；`python tools/check_update_install.py --exe <新版EXE> --old-exe <旧版EXE>` 只更新隔离的软件副本，运行软件自检，不会打开游戏。

## 设置汉化并启动游戏

打开软件，选择游戏目录，进入「汉化管理 → 当前汉化与切换」：

1. 先看上方“当前启用的汉化”。已有可用汉化时直接启动游戏，日常游玩和仅更新 BBMOD 软件都无需重新生成。手动安装的 BBMOD 包即使没存入方案，也会按实际启用状态显示。
2. 需要更换汉化时，在“切换方案（可选）”选择已保存方案。需要添加方案时，展开“添加方案 / 制作汉化（高级）”：用“收录已安装汉化”保存现有文件，用“导入汉化包”添加下载的包。仅在首次制作、修改译文或修复包时，进入“打开汉化制作工具”；此入口只打开编辑页，明确点击“制作并预览切换”才会生成新包。
3. 待切换的选择不代表正在使用。核对“尚未应用”的停用、启用及冲突文件，再点击“应用方案”或“应用并启动”；不想更换时点击“取消切换，沿用当前”。停用文件移至 `bbmod_disabled`，同名旧文件保留副本，不覆盖原包。
4. 平时点击顶部「启动游戏」，保留当前页面，按钮依次显示「正在启动…」「游戏运行中」，无需再去汉化页启动。只有所选方案尚未应用时，顶部显示「确认汉化方案」并进入切换预览。启动失败或超过 45 秒仍未检测到进程时会显示提示并允许重试；游戏退出后自动恢复按钮。两处启动入口共用状态，也会识别从 Steam 等入口启动的游戏。

BBMOD 独立汉化通过 MOD 的游戏界面和内置中文字体绘制地名；其他汉化沿用其自己的文件和游戏设置。启动指向当前选定目录的 `win32/BattleBrothers.exe`，不会改用另一个 Steam 安装目录。

### 中文地名与普通启动

独立汉化 `0.3.0-rc.7` 启用后，从 BBMOD、Steam 和游戏 EXE 启动都通过普通 MOD 显示中文地名。只有依赖已停用启动组件的旧汉化包需要换包，可导入现成新版包，或自行制作后应用；程序会给出对应提示。仅升级 BBMOD 桌面软件无需重做当前汉化。

手动安装官网汉化包时，将下载的 `mod_bbmod_zhcn.zip` 放入所选游戏的 `data` 子目录，无需解压；本地带版本号的发布 ZIP 也应保持只有一个汉化包启用。直接运行该游戏的 `win32/BattleBrothers.exe` 即可加载。旧汉化或修改相同资源的 MOD 应先移出 `data` 并保留备份。自定义路径可以手动选择，但软件内生成汉化仍会核对受支持的原版 EXE；修改版 EXE 和第三方整合包的兼容性未据此确认。

城镇、区域、营地和传奇地点共用 7,723 个校对后展开的显示名称。游戏实体名称、标签文字、区域名称和存档字段仍使用原值。营地的随机人名保留原版英文池及顺序，人物自身汉化不变；旧存档已经保存的中文名称不会自动改回英文。

中文标签在游戏原有 UI 中绘制，地图静止时复用上一帧，鼠标事件穿透到游戏。退出世界地图时清空标签。原版区域字体图像由普通 ZIP 资源覆盖，移除包即可恢复；地图显示因此依赖 UI 桥接正常加载。实现与验证边界见 [地图记录](localization/MOD_MAP_DISPLAY.md)。

方案和包副本保存在对应游戏目录的 `bbmod_localizations`，切换前生成校验过的备份。写入失败会恢复；中断后可点击「恢复上次切换」。种子远征未恢复时禁止切换和普通启动。开发测试副本的存档保护文件不参与汉化切换。

本功能管理 ZIP 形式的汉化。合集需要先解压并选取实际汉化包；直接修改过的 `.dat` 或额外安装器写入的文件不能靠停用 ZIP 自动还原。第三方包只作为完整文件管理，不导入其译文和脚本到独立词库。

当前功能已在临时目录验证切换、失败恢复、界面布局及启动分流。第三方汉化的实际运行兼容性尚未验收。

## 独立汉化的实际范围

当前版本 **0.3.0-rc.3** 的本体与官方 DLC 已提取目录共 **15,629 条文本**，涵盖 2,319 个来源文件：**13,433 条非地名文本及 2,196 条地名译文均已独立精修**。地名通过显示层呈现中文，原始英文数据不变。合并 186 条补充界面文本后，译文编辑页展示 **15,815 条文本**。正文目录为 `localization/full_catalog.json`，独立地名精修表为 `localization/reviewed_place_names.json`，均随 `dist/BBMOD-0.3.0-rc.15.exe` 分发；预生成包为 `dist/mod_bbmod_zhcn-0.3.0-rc.3.zip`。

- 源码与词库：`localization/catalog.json`、`full_catalog.json`、`runtime.js`、`fonts.css`。
- 基础包从官方归档读取 `ui/main.html` 和原版输入控件，加载自有显示适配器，并修补中文输入法的按键和内容更新事件。
- 不读取狐狸汉化 ZIP，不导入其译文、Squirrel 脚本、修改器或 hooks。
- 无需另装 MOD Hooks/MSU；为兼容已有玩法 MOD，随包提供公开的 Modding Script Hooks 21.1 运行文件并附署名。保留原版 Squirrel 指令、随机数调用和存档格式。地名生成函数中的两个姓名库引用指向自有配置中的原版英文数组，顺序及重复值不变；其余运行标识保持原样。正文只替换经过检查的显示文本常量。
- 界面使用 Noto Sans SC，地图使用 Noto Serif SC SemiBold，均附各自的 SIL OFL 许可证和来源记录。地图字体由本项目的适配器绘制，保留原来的位置和颜色，使用细描边并去除矩形底板。
- 正文和地名均显示「已校对」。地名精修表覆盖旧目录中的地名初稿，构建时展开为 7,723 个可显示名称，地图和对话使用相同结果；不会写回游戏名称或存档。全目录变量、数字、排版标记、换行、随机选句分隔符及分支内变量对应关系均通过检查，快捷键、品牌与制作人员署名按规则保留。
- 当前包完成离线结构和文本检查，并在用户授权的正常 Steam 目录抽查了普通启动、读取旧存档及中文城镇/区域显示。测试使用禁止存档保护，结束后恢复 MOD 并核对所有游戏数据和存档哈希。完整剧情、战斗流程及任意第三方 MOD 组合仍待验收。

译文目录在未安装游戏时也能编辑。自定义译文保存在 `%APPDATA%/BBMOD/l10n_independent_overrides.json`，不会导入旧版第三方脚本字段覆盖表。

需要制作自定义汉化包时，在「汉化管理 → 译文编辑与制作」制作并导出 ZIP，或者使用：

```powershell
python tools/build_l10n.py --game 'E:/SteamLibrary/steamapps/common/Battle Brothers' --output dist/mod_bbmod_zhcn-0.3.0-rc.3.zip
```

命令只生成文件，不安装。界面中的「制作并预览切换」把构建结果加入汉化方案；核对切换预览并点击「应用」后，才会停用列出的旧汉化或冲突 MOD，再安装所选包。仅继续使用当前汉化，无需执行制作步骤。已经修改过的游戏基座需要先自行还原。

### 当前离线验证与历史开发测试入口

2026-09-15 的测试副本位于 `app/build/full-l10n/game-check`，现仅用于离线验证。Steam 可能接管复制出来的游戏 EXE 并重新启动注册安装目录，因此新版会在启动前核对 Steam 清单并拒绝不匹配的副本。桌面的「BBMOD 独立汉化测试（开发中）」是历史入口，不再用于实机验证。

当前版本的离线验证包含 **2,281 个 Squirrel 字节码文件的原生读取、19,329 个原版函数的指令保持、205,339 个受保护常量检查，以及 45 个 JavaScript 文件的语法检查**。新增的独立地名查询和地图显示脚本与包内框架一起在离线解释器中运行检查。受保护常量仅允许两个已核对的地名姓名库引用变更；公开 MOD 框架的四个文件单独做字节校验。2026-09-17 经用户授权在正常 Steam 安装目录临时切换候选包，完成启动与地图抽查后恢复原 MOD 和设置，并保留测试日志；游戏数据和存档哈希一致。最终证据见 [地图记录](localization/MOD_MAP_DISPLAY.md)。

`localization/reviewed_refinement.json` 累计收录 **11,127 条独立修订文本及片段**，不能与完整目录数量相加。101 项离线回归通过；原生离线解释器执行包内代码，核对了 153 条完整特长及动态提示、3,800 个原版英文地名生成样例。地名专项检查覆盖 7,723 个地图及对话名称、直接启动→软件启动→再次直接启动、1 万次原生接口模拟调用和原始文字不变的绘制副本。显星 MOD 启用和停用、中文输入法与动态界面文本分别通过离线检查。详情见 [精修记录](localization/REFINEMENT.md) 和 [验证记录](localization/VALIDATION.md)。

中文字体与 Cinzel 标题字体随应用分发，避免依赖目标机器的字体配置。`Alt+1–5` 可切换工作台。

## MOD 与刷种子

### 显星、属性及评价 MOD 兼容

独立汉化不再打包 `world_town_screen_hire_dialog_module.js`，由原 MOD 保留自己的招募界面和回调，常用界面词语通过独立显示层翻译。随包提供原有 seedgen 资源中的 Modding Script Hooks 21.1 四个运行文件；不使用框架旧版的 `ui/main.html`，也不从狐狸汉化提取脚本。框架署名与来源随 ZIP 提供。

未启用显星 MOD 时，游戏使用原版招募界面，显示正常汉化的人物背景、雇佣费用及原版按钮；考察仍按原版规则揭示特性，不额外显示星级、属性预估、评价或移除按钮。只有启用该 MOD 后，才显示它提供的额外内容。汉化包本身不包含显星脚本。当前分发包已分别通过启用和停用两种状态的离线界面检查。

原显星 MOD 在招募时可能把属性记录追加到人物身世，并随人物存档保存。停用后，这类旧记录可能仍留在已经招募的人物身上；软件不会自动清除它们。本轮没有读取或修改存档。

`tools/check_star_rating.py` 离线执行本机实际「显星显属性带评价（影响存档）」脚本和界面，检查星级、属性、预估值、评价、中文背景、招募/考察/移除回调及新战役钩子重置。对本机 6 个 ZIP 的完整副本模拟切换到独立汉化，保留全部 5 个玩法 MOD，冲突为零；正式游戏目录只读。该检查不是游戏内验收，也不证明其余 MOD 的独立依赖全部满足。

切回原有狐狸汉化时，它与显星 MOD 原有的招募界面覆盖仍会在切换预览中提示；本轮没有修改第三方汉化或隐藏此冲突。

MOD 管理包括仓库、启停和集合方案。诊断结合脚本静态线索和上次游戏日志，不能证明任意第三方 MOD 完全兼容。

种子远征启动后，会按界面选定的起源和难度自动开始刷种子。文件会话保存在游戏根目录 `bbmod_seedgen_session/`：

1. 备份所有启用的 MOD，以及即将覆盖的已有种子配置和脚本。
2. 写入持久化清单后，再移除 MOD、注入种子生成器。
3. 停止后按 SHA-256 校验恢复原文件，删除本次新建的注入文件。
4. 程序中断后，再次开始远征会先恢复上次会话。
5. 会话期间意外变化的文件另存到 `bbmod_seedgen_session/preserved/`。

备份校验失败时保留清单并报告错误。旧版 `bbmod_seedgen_stash/` 遗留目录需要先检查恢复，不能声称已自动可靠修复旧版崩溃现场。
停止远征后，结果仍可查看、复制、导出 TXT。双击种子行可打开完整档案。

「我的种子 → 一键分享全部」将点击时本机已保存的完整种子及各自介绍公开到种子广场，包括搜索隐藏的条目，不含回收站；后来刷出的结果不会自动加入。已成功分享的种子沿用原链接，不再上传；资料不完整的条目跳过并在分享结果中列出原因。已分享的单条按钮变为「复制分享链接」。

上传逐条排队，显示进度和等待倒计时。遇到网站限流遵守服务器等待时间；临时网络 / 网站故障最多自动重试 3 次，仍失败则暂停整批。每条成功回执立即保存，停止或重启后再次点击可继续未成功的记录；服务器要求的等待时间也会保留。「停止上传」停止后续请求，已经发送的一条仍可能成功。「查看分享结果」可查看失败原因并复制链接。

网站按区分大小写的种子码、起源、游戏版本、战斗难度、经济难度和初始资金判重。相同档案重复上传返回原链接，保留原介绍，不新增记录；更换起源、版本或难度视为不同档案。

### 实时结果、停止与旧日志导入（源码 rc.6）

- 结果**边刷边显示**，无须等待结束。刷种子是持续搜索，默认没有“全部刷完”的终点。
- 点击「停止并恢复」可随时结束本次刷种子的游戏进程、保留已读结果并恢复此前的 MOD 和配置。停止时会继续收取日志尾部，未写完整的记录会标注出来。
- 在「生成设置」设定命中条数或运行分钟数即可自动停止；时限包含游戏加载。两项均不限时持续运行，两项都设定时以先达到的条件为准。日志每秒读取，结束时保留尾部结果，因此最终条数可能略多于目标。
- 结果栏的数量是软件实际收到的种子数；生成器的英文进度行里有些数量只表示人物初筛通过，后续还可能被地图或红装条件排除。
- 软件会查找 Windows 实际文档目录、OneDrive 目录及日志自报位置，并确认本次会话。游戏仍在加载时可等待；若游戏已在刷而表格仍为空，用「日志 → 查看当前读取位置」核对，并选择包含 `log.html` 的实际日志目录。
- 已经刷出的 `log.txt` 或 `log.html`，可在停止后用「日志 → 导入已有种子日志」导入中文档案，无需再次开游戏。历史日志不按当前筛选条件重新过滤，缺失的起源、难度和末条结束标记不会被补造。
- 默认档案按兄弟列出初始值、11 级预估、星级、中文特质，以及已记录的城镇和红装数据。双击后勾选「查看英文原始记录」可排查原始字段。复制和 TXT 导出按当前格式生成中文文本。

### 筛选条件

默认按明确属性筛选：例如至少3名兄弟，同时满足11级预估近战命中≥90、近战防御≥25；选择“不限”的属性不参与筛选。生命、决心、疲劳上限等门槛放在“其他属性”中。地图页可直接设置港口、城镇、甲店数量；只有当前寻找模式涉及的条件页可用。

「地图与港口」新增「南北港」「竞技场港」，可单独或同时勾选。南北港沿用生成器的地图分区，要求左上北港、左下南港各至少一座，中间港和东港不代替南北港；竞技场港要求竞技场所在城邦同时有港口。勾选项与港口、城镇、甲店数量门槛必须同时满足，未勾选表示不限。地图条件会自动保存，在「人物 + 地图」「只找地图」「人物 + 地图 + 红装」模式生效；历史种子库和导入日志不按这些生成条件重新过滤。

「营地红装」可选择「红装总数」或「指定红武器」。指定筛选支持 50 种具体武器及单手近战、双手近战、远程／投掷等大类，可设置至少几件，以及可选的伤害、穿甲品质。品质表示加成在其可随机范围内的位置，100% 为满值；0% 仍要求出现该加成，「不限」才是不要求。每件计入数量的武器都必须同时满足所选条件。两种筛选方式独立切换，选择会保存。

只刷红武器时，选择「寻找 → 只找红装」，在「营地红装 → 指定红武器」选择类型和数量后开始远征；也可与人物、地图条件组合。例如红标枪至少 1 件，伤害品质与穿甲品质均不低于 75%。范围是生成时营地里的红装，可用类型取决于游戏和已安装的 DLC。结果详情保留具体武器名、品质及最终属性。本次完成离线脚本判定、主循环分流和桌面回归验证，尚未进行新的实机长时间搜索。

在「开局兄弟 → 属性与特质 → 特质筛选」可搜索原版 58 种开局特质，为每项选择「不限」「必须具备」或「不能拥有」。必选项可以要求全部具备，也可允许任意一项；与能力值组合时，计入人数的每名兄弟必须同时满足整套条件。排除项只限制这些兄弟，不会因其他队员拥有该特质而淘汰整个种子。

例如：至少 1 人，近战命中 ≥90、近战防御 ≥25，全部具备「高大（巨人）」与「铁肺」，并排除「笨拙」。想忽略能力值时选择「仅按特质筛选」。互斥特质的全部匹配会提示修正；起源可能限制某些特质出现，不能保证任意组合都有种子。沿用起源预设和高级评分模式使用各自原有规则，不附加此特质面板的选择。

特质选择会保存；结果的种子档案按人物显示中文特质，TXT 导出保留这些详情。「只找开局兄弟（快）」已修正为执行人物筛选分支。此版本 111 项离线回归通过，其中实际 Squirrel 判定器执行 16 个样例检查同一人物匹配、任意／全部、排除、人数和门槛边界；没有启动游戏。

11级数值按每级提升该属性计算，逐级模拟或星级平均值均为预估；不同属性同时成长仍受实际加点选择影响。

### 自动开局与汉化

在软件里选好起源和条件，点击「开始远征」后会启动当前游戏目录，等待主菜单加载就绪，再自动按所选起源新建战役。无需进游戏再选一遍，也不依赖固定秒数或鼠标位置。起源不可用或游戏实际设置不符时明确报错；进度区显示等待菜单、加载战役、生成中及错误状态。

「生成设置」可选战斗难度、经济难度、初始资金，默认老兵／老兵／中。起源和这些设置会保存，并写入结果详情及弹幕 TXT；复现红装请使用相同起源、难度、游戏版本和 DLC。软件只接收本次会话标记之后的日志，不会混入上次刷种子的记录。

刷种子准备阶段会备份并暂时移出独立汉化和其他已启用的 ZIP/RAR MOD，结束后恢复；官方 DAT 文件不改动。独立汉化包不参与这次生成。若修改直接合并进 DAT，移出 MOD 无法撤销，但仅凭 ZIP 条目日期无法判断是否汉化、是否重打包或是否改变生成逻辑。原先“汉化重打包、种子失真”的日期误判弹窗已移除，日期仅在营地诊断里作为信息显示。

自动开局经过离线 Squirrel 验证，使用本机提取的原游戏菜单脚本覆盖 14 个起源、42 组设置及失败分支；未启动游戏，实际游戏内流程仍待验收。

“队伍平均分”保留在高级评分中：每名兄弟按职业名额分配职业，汇总其评分后取平均。个人评分综合初始属性、11级预估属性与特性；近战权重为命中35%、近防30%、疲劳20%、生命10%、决心5%。分数可以低于0或超过1，0.8不能直接换算为某项属性或百分位。评分条件按严格大于比较，属性条件按大于等于比较。完整解释可在界面点击“评分说明”。

### TXT、复制与弹幕模式

- 表格上方常驻“复制种子码”：选中后直接点击或在表格里按 Ctrl+C，不需要展开档案或切换格式。Ctrl / Shift 多选后按列表顺序逐行复制，保留大小写，不包含搜索隐藏的条目。
- 展开档案后的“复制文案”和表格内 Ctrl+Shift+C 复制当前行文案；输出格式可选“种子档案”“弹幕模式（一行一条）”“仅种子码”，TXT 导出沿用所选格式。
- 开启“点选即复制”后，单击种子行可复制当前格式的文案，格式和开关会记住。纯种子码复制不改变这些设置，新结果加入时不自动改动剪贴板。
- 弹幕开场白可选“卡大货了？”“缺大哥？”等，也可自填。自动亮点只使用日志记录的港口、预估属性和红装数量。
- 金鹅位置、乘船路线等可在“补充介绍 / 路线”手动填写，按种子码与实际起源保存。程序不会凭空生成未采集的地标和行走路线。
- TXT 使用带 BOM 的 UTF-8，保留种子大小写；没有命中结果时禁用导出。

## 打包

**2026-09-17 网站发布 rc10。** 普通 MOD 提供中文地名显示，旧注入启动器、DLL、加载代码和构建入口均已从当前实现删除。旧组件的历史检测记录仍保留，参见 [历史排查记录](docs/history/defender-review.md)；新版验证见 [地图记录](localization/MOD_MAP_DISPLAY.md)。

安装 `requirements-dev.txt` 后：

```powershell
python tools/build_icons.py
python -m PyInstaller --noconfirm BBMOD.spec
python tools/package_check.py --exe dist/BBMOD-0.3.0-rc.23.exe
```

当前 spec 保留单文件构建，成品按实际软件版本命名，例如 `dist/BBMOD-0.3.0-rc.23.exe`，包含完整独立精修词库、字体、图标、种子脚本和普通 MOD 地图界面代码。`package_check.py` 会拒绝携带旧注入组件的构建。内置 MOD 资源合集仍从 EXE 周边仓库目录寻找，不把第三方汉化并入应用。

网站发布提供带版本号的主下载文件，例如 `BBMOD-0.3.0-rc.15.exe`。本版更新器优先读取官网。若另行发布到 GitHub，旧 rc.4／rc.5 更新器仍需要内容完全一致的 `BBMOD.exe` 兼容附件；更新器会校验下载地址、大小和 SHA256。

地名专项检查：先构建预览 ZIP，再运行 `python tools/check_mod_map.py --package <ZIP路径>`。该工具使用离线 Squirrel 解释器、Node.js 和模拟 UI，验证连接、缩放、静止帧复用、离开地图清屏、原名保留与错误恢复；不启动游戏。

打包时将依赖搜索范围限定在 Python 与 Windows 目录，避免其他工具的同名 DLL 混入。`package_check.py` 检查 EXE 内资源，并使用临时用户配置运行桌面自检；不会安装汉化或启动游戏。
