# BBMOD · 战团整备所

面向《战场兄弟》1.5.2.3 的本地桌面工具：营地诊断、MOD 军械库、方案管理、汉化管理、种子远征、装备百科与反馈。

当前桌面版本为 **0.4.0**（以 `core/version.py` 为准），配套独立汉化包为 **0.3.0-rc.9**。官网 **https://bbmod.com** 统一提供软件下载、更新、在线军械库和方案广场。各版本的改动见 [releases/](releases/)，当前版本见 [0.4.0 说明](releases/0.4.0.md)；固定编号和打包规则见 [版本约定](docs/versioning.md)。网站部署与发布记录见 [web/README.md](../web/README.md) 和 [web/deploy/](../web/deploy/)。

## 下载与升级

[网站下载](https://bbmod.com/downloads/)提供带版本号的单文件程序 `BBMOD-<版本>.exe`，内置独立汉化词库、字体与普通 MOD 显示资源，无需安装 Python。请自行安装受支持的 Steam 原版 1.5.2.3 及相应 DLC；首次运行后选择游戏目录。第三方汉化和显星 MOD 需要另外安装。

- rc.36 及更新版本可在「设置 → 检查更新」直接升级；更早的旧官网版本请从官网手动下载并更换最新版，之后使用软件内更新。
- 配套[独立汉化包](https://bbmod.com/mods/22c174ed-fc9d-4dbb-9642-44831ce694e8/)为 `0.3.0-rc.9`，修复了地名组件换行格式不匹配及 Modern Hooks 的 FPS 界面覆盖，详见[发布记录](../web/deploy/deployment-localization-rc9-2026-09-27.md)。已启用该包时无需重新生成；仅更新桌面软件也不需要重做汉化。

## 界面与导航

各工作台采用木质底板、铆钉金属边框、卷轴面板与暗红旗帜选中态。
手绘风格营地插画与头盔盾徽由内置 ImageGen 生成，已随应用打包；盾徽同时用于窗口、任务栏与 EXE，导航和操作按钮使用金属徽章图标。
素材与生成提示词见 `assets/art-direction.json`。
中文字体与 Cinzel 标题字体随应用分发，避免依赖目标机器的字体配置。

侧栏按顺序为营地总览、MOD 军械库、方案管理、汉化管理、种子远征、装备百科、反馈与建议和设置（固定在最下方），可用 `Alt+1`–`Alt+8` 切换。左上角的 BBMOD 图标可点击打开官网。

## 设置汉化并启动游戏

打开软件，选择游戏目录，进入「汉化管理 → 当前汉化与切换」：

1. 先看上方“当前启用的汉化”。已有可用汉化时直接启动游戏，日常游玩和仅更新 BBMOD 软件都无需重新生成。手动安装的 BBMOD 包即使没存入方案，也会按实际启用状态显示。
2. 需要更换汉化时，在“切换方案（可选）”选择已保存方案。需要添加方案时，展开“添加方案 / 制作汉化（高级）”：用“收录已安装汉化”保存现有文件，用“导入汉化包”添加下载的包。仅在首次制作、修改译文或修复包时，进入“打开汉化制作工具”；此入口只打开编辑页，明确点击“制作并预览切换”才会生成新包。
3. 待切换的选择不代表正在使用。核对“尚未应用”的停用、启用及冲突文件，再点击“应用方案”或“应用并启动”；不想更换时点击“取消切换，沿用当前”。停用文件移至 `bbmod_disabled`，同名旧文件保留副本，不覆盖原包。
4. 平时点击顶部「启动游戏」，保留当前页面，按钮依次显示「正在启动…」「游戏运行中」，无需再去汉化页启动。只有所选方案尚未应用时，顶部显示「确认汉化方案」并进入切换预览。启动失败或超过 45 秒仍未检测到进程时会显示提示并允许重试；游戏退出后自动恢复按钮。两处启动入口共用状态，也会识别从 Steam 等入口启动的游戏。

停用会保留文件和方案，以便重新启用；重新启用时移走内容相同的停用副本，避免军械库重复显示。要彻底移除安装文件，在军械库中选中对应汉化并「卸载」。以前留下的方案或尚未应用的方案，可在汉化页选中后点击「删除方案」清理名称；该操作保留游戏文件、原包、汉化库副本和恢复备份。没有已保存方案或已启用的 BBMOD 包时，不再显示空的 BBMOD 汉化选项。

BBMOD 独立汉化通过 MOD 的游戏界面和内置中文字体绘制地名；其他汉化沿用其自己的文件和游戏设置。启动指向当前选定目录的 `win32/BattleBrothers.exe`，不会改用另一个 Steam 安装目录。

### 中文地名与普通启动

独立汉化 `0.3.0-rc.8` 及更新版本启用后，从 BBMOD、Steam 和游戏 EXE 启动都通过普通 MOD 显示中文地名，程序不再调用旧中文注入组件。只有依赖已停用启动组件的旧汉化包需要换包，可导入现成新版包，或自行制作后应用；程序会给出对应提示。仅升级 BBMOD 桌面软件无需重做当前汉化。

手动安装官网汉化包时，将下载的 `mod_bbmod_zhcn.zip` 放入所选游戏的 `data` 子目录，无需解压；本地带版本号的发布 ZIP 也应保持只有一个汉化包启用。直接运行该游戏的 `win32/BattleBrothers.exe` 即可加载。旧汉化或修改相同资源的 MOD 应先移出 `data` 并保留备份。自定义路径可以手动选择，但软件内生成汉化仍会核对受支持的原版 EXE；修改版 EXE 和第三方整合包的兼容性未据此确认。

城镇、区域、营地和传奇地点共用 7,723 个校对后展开的显示名称。游戏实体名称、标签文字、区域名称和存档字段仍使用原值。营地的随机人名保留原版英文池及顺序，人物自身汉化不变；旧存档已经保存的中文名称不会自动改回英文。

中文标签在游戏原有 UI 中绘制，地图静止时复用上一帧，鼠标事件穿透到游戏。退出世界地图时清空标签。原版区域字体图像由普通 ZIP 资源覆盖，移除包即可恢复；地图显示因此依赖 UI 桥接正常加载。实现与验证边界见 [地图记录](localization/MOD_MAP_DISPLAY.md)。

方案和包副本保存在对应游戏目录的 `bbmod_localizations`，切换前生成校验过的备份。写入失败会恢复；中断后可点击「恢复上次切换」。种子远征未恢复时禁止切换和普通启动。开发测试副本的存档保护文件不参与汉化切换。

本功能管理 ZIP 形式的汉化。合集需要先解压并选取实际汉化包；直接修改过的 `.dat` 或额外安装器写入的文件不能靠停用 ZIP 自动还原。第三方包只作为完整文件管理，不导入其译文和脚本到独立词库。

切换、失败恢复、界面布局及启动分流已在临时目录验证。第三方汉化的实际运行兼容性尚未验收。

## 独立汉化的实际范围

本体与官方 DLC 已提取目录共 **15,629 条文本**，涵盖 2,319 个来源文件：**13,433 条非地名文本及 2,196 条地名译文均已独立精修**。地名通过显示层呈现中文，原始英文数据不变。合并 186 条补充界面文本后，译文编辑页展示 **15,815 条文本**。此后又逐句通读 15,819 条中文文本及随机分支，修订 634 条，统一术语，改善剧情措辞与动态拼接，补齐南方人物称呼顺序并修正原版几处文字排版错误，详见[逐句审校记录](docs/localization-sentence-review-20260919.md)。正文目录为 `localization/full_catalog.json`，独立地名精修表为 `localization/reviewed_place_names.json`，均随桌面 EXE 分发；现成汉化包可从官网下载，也可按下文自行制作。

- 源码与词库：`localization/catalog.json`、`full_catalog.json`、`runtime.js`、`fonts.css`。
- 基础包从官方归档读取 `ui/main.html` 和原版输入控件，加载自有显示适配器，并修补中文输入法的按键和内容更新事件。
- 不读取狐狸汉化 ZIP，不导入其译文、Squirrel 脚本、修改器或 hooks。
- 无需另装 MOD Hooks/MSU；为兼容已有玩法 MOD，随包提供公开的 Modding Script Hooks 21.1 运行文件并附署名。保留原版 Squirrel 指令、随机数调用和存档格式。地名生成函数中的两个姓名库引用指向自有配置中的原版英文数组，顺序及重复值不变；其余运行标识保持原样。正文只替换经过检查的显示文本常量。
- 界面使用 Noto Sans SC，地图使用 Noto Serif SC SemiBold，均附各自的 SIL OFL 许可证和来源记录。地图字体由本项目的适配器绘制，保留原来的位置和颜色，使用细描边并去除矩形底板。
- 正文和地名均显示「已校对」。地名精修表覆盖旧目录中的地名初稿，构建时展开为 7,723 个可显示名称，地图和对话使用相同结果；不会写回游戏名称或存档。全目录变量、数字、排版标记、换行、随机选句分隔符及分支内变量对应关系均通过检查，快捷键、品牌与制作人员署名按规则保留。
- 汉化包完成离线结构和文本检查，并曾在用户授权的正常 Steam 目录抽查普通启动、读取旧存档及中文城镇/区域显示。测试使用禁止存档保护，结束后恢复 MOD 并核对所有游戏数据和存档哈希。完整剧情、战斗流程及任意第三方 MOD 组合仍待验收。

译文目录在未安装游戏时也能编辑。自定义译文保存在 `%APPDATA%/BBMOD/l10n_independent_overrides.json`，不会导入旧版第三方脚本字段覆盖表。

需要制作自定义汉化包时，在「汉化管理 → 译文编辑与制作」制作并导出 ZIP，或者使用：

```powershell
python tools/build_l10n.py --game '<游戏目录>' --output dist/mod_bbmod_zhcn-<版本>.zip
```

命令只生成文件，不安装。界面中的「制作并预览切换」把构建结果加入汉化方案；核对切换预览并点击「应用」后，才会停用列出的旧汉化或冲突 MOD，再安装所选包。仅继续使用当前汉化，无需执行制作步骤。已经修改过的游戏基座需要先自行还原。

离线验证范围、校对词表与历史实机检查见下文「[独立汉化验证记录](#独立汉化验证记录)」。

## MOD 军械库

MOD 管理包括仓库、启停和集合方案。诊断结合脚本静态线索和上次游戏日志，不能证明任意第三方 MOD 完全兼容。

### 已安装 MOD 与直接更新

「MOD 军械库 → 已安装」列出中文名称、本地版本和官网版本。进入军械库后在后台检查官网，更新列直接显示「已是最新」「版本待确认」「未匹配官网」或「本地版本较新」，方便判断没有更新按钮的原因；确认有新版时显示行内「更新」按钮。

- 点击「更新」直接从官网下载、校验并安装，无需再次确认。保留原文件名和启用或禁用状态，旧包自动备份，可在在线军械库恢复上一版。下载进度、取消下载和失败原因直接显示在已安装页面；下载、文件身份或写入校验失败时保留原包。
- 手动安装的包通过官网发布文件校验值、可信安装记录或可比较的包版本识别。测试版序号按数字比较（例如 `0.29.0-preview.12` → `0.29.0-preview.13`），也能识别从 preview 升级到 rc 或正式版；脚本内部编号与官网版本不同的包不直接比较。没有版本信息的包显示「未识别」，无法核实版本时继续等待确认，不误报更新。已有的 BBMOD 装备读取器也显示中文名称和版本。
- 游戏运行、刷种子或有未完成操作时禁止修改 MOD。

「禁用」保留文件，「卸载」删除所选安装文件及关联在线安装记录。卸载汉化的最后一份安装副本时，同时移除引用它的已保存汉化方案，汉化页自动刷新并沿用当前配置；方案中的其他文件、仓库原包、游戏原始档案和存档保留。文件删除与记录清理共同恢复，避免卸载一半留下残名。方案应用前显示启用/禁用清单，缺少文件时停止；意外中断后可点击「恢复上次操作」。本地 ZIP 和内嵌 ZIP 在写入游戏目录前一起校验；真正的 RAR 需先解压后选择 MOD ZIP。

### 在线军械库

进入「MOD 军械库 → 在线军械库」，默认使用官网 `https://bbmod.com`；自托管网站地址位于「自定义源（高级）」。作品列表占用窗口的可用高度，详情固定在底部。支持搜索作者作品、查看说明、下载校验并安装；更新时备份旧版，保留启用/禁用状态，可恢复上一版。未受管理或已手动修改的同名 ZIP 不会被覆盖。营地诊断支持常见版本比较表达式，无法识别的格式会提示人工确认；DLC 和游戏兼容性仍需阅读作者说明。网站部署见 [web/README.md](../web/README.md)。

下载汉化包和 MOD 时显示大小与百分比，正常传输不会因超过固定时长而中断。连接短暂中断会最多重试 4 次，服务器支持时自动续传；取消后停止重试。共享方案文件使用相同的下载逻辑。下载大小、官网清单中的 SHA-256 和压缩包均校验通过后才安装。

## 方案管理

左侧「方案管理」（Alt+3）包含「本地方案」和「网站方案」。本地可搜索、查看 MOD 清单、保存当前组合、预览应用、重命名、删除和分享。删除仅移除本地方案记录，保留 MOD 文件和网站方案；同名保存会先确认覆盖。分享成功后保存链接，可随时复制；导入方案改名后仍按原共享版本应用，不会重复创建另一份方案。

「网站方案」直接读取网站已有的公开方案，支持搜索、分页、介绍、网页详情和复制链接。选择「预览并应用」后查看完整清单与本机变更，再下载缺失文件并应用。「MOD 军械库 → 导入共享方案」打开这个列表；原来的链接 / 编号导入保留在「通过链接导入…」。无需选择游戏目录即可浏览网站，应用时再选择目录。断网不会影响本地方案管理，可手动刷新重试。

方案列表与在线军械库共用网站来源；自托管地址在「在线军械库 → 自定义源（高级）」设置。列表依赖网站的 `GET /api/v1/profiles/` 搜索分页接口；尚未更新服务端的自托管网站仍可使用链接导入，更新服务端后启用列表。

### 共享 MOD 方案

在「MOD 军械库 → 已安装」启用所需 MOD 并保存方案，点击「分享方案」，填写选填介绍。管理器会核对网站已有文件，预览哪些可复用、哪些需要补传及上传大小；点击「上传并分享」后，只上传网站缺少的文件，全部到齐才发布分享链接。网站已有介绍但没有实际托管文件的 MOD 也需要补传。同名不同内容视为不同版本；改名但内容完全一致的文件可复用。旧的本地方案只记录文件名，分享时固定的是本机当前对应文件的内容。

接收者可在「方案管理 → 网站方案」直接选择方案，或打开方案网页点击「在 BBMOD 中应用方案」；手动粘贴链接位于「通过链接导入…」。预览会列出需下载、安装或切换、禁用的 MOD；点击「下载并应用」后先复用本机一致的文件，再下载缺失文件，全部通过 SHA-256、ZIP 结构和依赖冲突检查后一次应用。会保存为本地方案，重名时保留已有方案另存新名。之后从「应用方案」选择这份共享方案，也会核对网站并补齐文件。方案以分享时的文件为准，不自动换成最新版本。

下载或校验失败不更改游戏目录；应用写入失败自动回滚，中断后可用「恢复上次操作」。成功操作的原文件和对应清单保留在 `bbmod_disabled/operations/<操作编号>/`，应用完成时会显示备份目录。游戏运行、种子远征、其他文件操作或未完成恢复期间不允许应用。

分享的范围是方案中直接安装的 MOD ZIP，含 ZIP 内的设置；不包含游戏本体、DLC、存档和 ZIP 外的个人配置。沿用网站的文件检查，RAR、套娃 ZIP、程序安装器等须先整理为可直接安装的 MOD。单文件上限 100 MB，方案上限 200 个 MOD / 2 GB。未知的游戏内兼容性仍需玩家验证；需要的 DLC 可写入方案介绍。官网的[方案广场](https://bbmod.com/profiles/)展示公开方案。

## 种子远征

种子远征启动后，会按界面选定的起源和难度自动开始刷种子。文件会话保存在游戏根目录 `bbmod_seedgen_session/`：

1. 备份所有启用的 MOD，以及即将覆盖的已有种子配置和脚本。
2. 写入持久化清单后，再移除 MOD、注入种子生成器。
3. 停止后按 SHA-256 校验恢复原文件，删除本次新建的注入文件。
4. 程序中断后，再次开始远征会先恢复上次会话。
5. 会话期间意外变化的文件另存到 `bbmod_seedgen_session/preserved/`。

备份校验失败时保留清单并报告错误。旧版 `bbmod_seedgen_stash/` 遗留目录需要先检查恢复，不能声称已自动可靠修复旧版崩溃现场。
停止远征后，结果仍可查看、复制、导出 TXT。双击种子行可打开完整档案。

### 阿飞远征团起源

阿飞远征团起源可选择「只找地图」「只找红装」「地图 + 红装」。先在 MOD 军械库安装并启用阿飞主包，再在种子远征中选择「阿飞远征团（固定人物）」。开局三人的身份和基础属性固定，人物筛选会禁用；地图条件与营地红装条件可以同时使用。

搜索时保留所选阿飞主包并加载随生成器提供的 Legacy Hooks，暂时移出其他 MOD（包括可选阿飞 DLC），停止后恢复原组合。每轮重新执行游戏原生的新建战役流程，保留人物生成、出生位置和营地模拟的随机数顺序，重置世界标记与名册弹窗。这个路径会生成完整地图，速度低于官方起源的快速人物筛选。

档案与原始生成日志记录游戏版本、三项开局难度、官方 DLC 组合，以及阿飞主包和 Hooks 的版本与 SHA-256。纯数字阿飞版本表示脚本内部版本；复现时以同一主包文件为准。新环境使用分享格式 2，旧官方种子格式 1 仍可导入；不同环境下的同一码分别保存。自托管网站需要同步更新服务端后才能接收阿飞种子。

红装筛选范围是新战役开始时营地中已生成的红装，不包括后续商店刷新、悬赏和事件奖励。筛出的种子用于**新建战役**，不会改写已有存档。当前仅适配阿飞起源，其他自制起源需要单独检查开局流程。真实游戏复现检查见「[真实游戏目录工具](#真实游戏目录工具)」。

### 分享种子

「我的种子 → 一键分享全部」将点击时本机已保存的完整种子及各自介绍公开到种子广场，包括搜索隐藏的条目，不含回收站；后来刷出的结果不会自动加入。已成功分享的种子沿用原链接，不再上传；资料不完整的条目跳过并在分享结果中列出原因。已分享的单条按钮变为「复制分享链接」。

上传逐条排队，显示进度和等待倒计时。遇到网站限流遵守服务器等待时间；临时网络 / 网站故障最多自动重试 3 次，仍失败则暂停整批。每条成功回执立即保存，停止或重启后再次点击可继续未成功的记录；服务器要求的等待时间也会保留。「停止上传」停止后续请求，已经发送的一条仍可能成功。「查看分享结果」可查看失败原因并复制链接。

网站按区分大小写的种子码、起源、游戏版本、战斗难度、经济难度和初始资金判重。相同档案重复上传返回原链接，保留原介绍，不新增记录；更换起源、版本或难度视为不同档案。

### 实时结果、停止与旧日志导入

- 结果**边刷边显示**，无须等待结束。刷种子是持续搜索，默认没有“全部刷完”的终点。
- 日志在后台读取、结果批量保存，大量命中时不会堵塞界面。「我的种子」历史列表每页显示 500 条，搜索、分享与导出仍覆盖全部结果。
- 点击「停止并恢复」可随时结束本次刷种子的游戏进程、保留已读结果并恢复此前的 MOD 和配置。停止时会继续收取日志尾部，未写完整的记录会标注出来。
- 在「生成设置」设定命中条数或运行分钟数即可自动停止；时限包含游戏加载。两项均不限时持续运行，两项都设定时以先达到的条件为准。日志每秒读取，结束时保留尾部结果，因此最终条数可能略多于目标。
- 结果栏的数量是软件实际收到的种子数；生成器的英文进度行里有些数量只表示人物初筛通过，后续还可能被地图或红装条件排除。
- 软件会查找 Windows 实际文档目录、OneDrive 目录及日志自报位置，并确认本次会话。游戏仍在加载时可等待；若游戏已在刷而表格仍为空，用「日志 → 查看当前读取位置」核对，并选择包含 `log.html` 的实际日志目录。
- 已经刷出的 `log.txt` 或 `log.html`，可在停止后用「日志 → 导入已有种子日志」导入中文档案，无需再次开游戏。历史日志不按当前筛选条件重新过滤，缺失的起源、难度和末条结束标记不会被补造。
- 默认档案按兄弟列出初始值、11 级预估、星级、中文特质，以及已记录的城镇和红装数据。双击后勾选「查看英文原始记录」可排查原始字段。复制和 TXT 导出按当前格式生成中文文本。

### 筛选条件

默认按明确属性筛选：例如至少3名兄弟，同时满足11级预估近战命中≥90、近战防御≥25；选择“不限”的属性不参与筛选。生命、决心、疲劳上限等门槛放在“其他属性”中。地图页可直接设置港口、城镇、甲店数量；只有当前寻找模式涉及的条件页可用。

「地图与港口」提供「南北港」「竞技场港」，可单独或同时勾选。南北港沿用生成器的地图分区，要求左上北港、左下南港各至少一座，中间港和东港不代替南北港；竞技场港要求竞技场所在城邦同时有港口。勾选项与港口、城镇、甲店数量门槛必须同时满足，未勾选表示不限。地图条件会自动保存，在「人物 + 地图」「只找地图」「人物 + 地图 + 红装」模式生效；历史种子库和导入日志不按这些生成条件重新过滤。

「营地红装」可选择「红装总数」或「指定红武器」。指定筛选支持 50 种具体武器及单手近战、双手近战、远程／投掷等大类，可设置至少几件，以及可选的伤害、穿甲品质。品质表示加成在其可随机范围内的位置，100% 为满值；0% 仍要求出现该加成，「不限」才是不要求。每件计入数量的武器都必须同时满足所选条件。两种筛选方式独立切换，选择会保存。

只刷红武器时，选择「寻找 → 只找红装」，在「营地红装 → 指定红武器」选择类型和数量后开始远征；也可与人物、地图条件组合。例如红标枪至少 1 件，伤害品质与穿甲品质均不低于 75%。范围是生成时营地里的红装，可用类型取决于游戏和已安装的 DLC。结果详情保留具体武器名、品质及最终属性。该筛选经过离线脚本判定、主循环分流和桌面回归验证，尚未进行实机长时间搜索。

在「开局兄弟 → 属性与特质 → 特质筛选」可搜索原版 58 种开局特质，为每项选择「不限」「必须具备」或「不能拥有」。必选项可以要求全部具备，也可允许任意一项；与能力值组合时，计入人数的每名兄弟必须同时满足整套条件。排除项只限制这些兄弟，不会因其他队员拥有该特质而淘汰整个种子。

例如：至少 1 人，近战命中 ≥90、近战防御 ≥25，全部具备「高大（巨人）」与「铁肺」，并排除「笨拙」。想忽略能力值时选择「仅按特质筛选」。互斥特质的全部匹配会提示修正；起源可能限制某些特质出现，不能保证任意组合都有种子。沿用起源预设和高级评分模式使用各自原有规则，不附加此特质面板的选择。

特质选择会保存；结果的种子档案按人物显示中文特质，TXT 导出保留这些详情。「只找开局兄弟（快）」执行人物筛选分支。特质判定由实际 Squirrel 判定器离线执行 16 个样例，检查同一人物匹配、任意／全部、排除、人数和门槛边界；没有启动游戏。

11级数值按每级提升该属性计算，逐级模拟或星级平均值均为预估；不同属性同时成长仍受实际加点选择影响。

### 自动开局与汉化

在软件里选好起源和条件，点击「开始远征」后会启动当前游戏目录，等待主菜单加载就绪，再自动按所选起源新建战役。无需进游戏再选一遍，也不依赖固定秒数或鼠标位置。起源不可用或游戏实际设置不符时明确报错；进度区显示等待菜单、加载战役、生成中及错误状态。

「生成设置」可选战斗难度、经济难度、初始资金，默认老兵／老兵／中。起源和这些设置会保存，并写入结果详情及弹幕 TXT；复现红装请使用相同起源、难度、游戏版本和 DLC。软件只接收本次会话标记之后的日志，不会混入上次刷种子的记录。

刷种子准备阶段会备份并暂时移出独立汉化和其他已启用的 ZIP/RAR MOD，结束后恢复；官方 DAT 文件不改动。独立汉化包不参与这次生成。若修改直接合并进 DAT，移出 MOD 无法撤销，但仅凭 ZIP 条目日期无法判断是否汉化、是否重打包或是否改变生成逻辑。原先“汉化重打包、种子失真”的日期误判弹窗已移除，日期仅在营地诊断里作为信息显示。

自动开局经过离线 Squirrel 验证，使用本机提取的原游戏菜单脚本覆盖 14 个起源、42 组设置及失败分支；未启动游戏，实际游戏内流程仍待验收。

“队伍平均分”保留在高级评分中：每名兄弟按职业名额分配职业，汇总其评分后取平均。个人评分综合初始属性、11级预估属性与特性；近战权重为命中35%、近防30%、疲劳20%、生命10%、决心5%。分数可以低于0或超过1，0.8不能直接换算为某项属性或百分位。评分条件按严格大于比较，属性条件按大于等于比较。完整解释可在界面点击“评分说明”。

### TXT、复制与弹幕模式

- 表格上方常驻“复制种子码”：选中后直接点击或在表格里按 Ctrl+C，不需要展开档案或切换格式。Ctrl / Shift 多选后按列表顺序逐行复制，保留大小写，不包含搜索隐藏的条目。
- 展开档案后的“复制文案”和表格内 Ctrl+Shift+C 复制当前行文案；输出格式可选“种子档案”“弹幕模式（一行一条）”“仅种子码”，TXT 导出沿用所选格式。
- 开启“点选即复制”后，单击种子行可复制当前格式的文案，格式和开关会记住。纯种子码复制不改变这些设置，新结果加入时不自动改动剪贴板。
- 弹幕开场白可选“卡大货了？”“缺大哥？”等，也可自填。自动亮点只使用日志记录的港口、预估属性和红装数量。
- 金鹅位置、乘船路线等可在“补充介绍 / 路线”手动填写，按种子码与实际起源保存。程序不会凭空生成未采集的地标和行走路线。
- TXT 使用带 BOM 的 UTF-8，保留种子大小写；没有命中结果时禁用导出。

### 显星、属性及评价 MOD 兼容

独立汉化不再打包 `world_town_screen_hire_dialog_module.js`，由原 MOD 保留自己的招募界面和回调，常用界面词语通过独立显示层翻译。随包提供原有 seedgen 资源中的 Modding Script Hooks 21.1 四个运行文件；不使用框架旧版的 `ui/main.html`，也不从狐狸汉化提取脚本。框架署名与来源随 ZIP 提供。

未启用显星 MOD 时，游戏使用原版招募界面，显示正常汉化的人物背景、雇佣费用及原版按钮；考察仍按原版规则揭示特性，不额外显示星级、属性预估、评价或移除按钮。只有启用该 MOD 后，才显示它提供的额外内容。汉化包本身不包含显星脚本。分发包已分别通过启用和停用两种状态的离线界面检查。

原显星 MOD 在招募时可能把属性记录追加到人物身世，并随人物存档保存。停用后，这类旧记录可能仍留在已经招募的人物身上；软件不会自动清除它们，相关检查也没有读取或修改存档。

`tools/check_star_rating.py` 离线执行本机实际「显星显属性带评价（影响存档）」脚本和界面，检查星级、属性、预估值、评价、中文背景、招募/考察/移除回调及新战役钩子重置。对本机 6 个 ZIP 的完整副本模拟切换到独立汉化，保留全部 5 个玩法 MOD，冲突为零；正式游戏目录只读。该检查不是游戏内验收，也不证明其余 MOD 的独立依赖全部满足。

切回原有狐狸汉化时，它与显星 MOD 原有的招募界面覆盖仍会在切换预览中提示；BBMOD 不修改第三方汉化，也不隐藏此冲突。

## 装备百科

「装备百科」默认打开「装备表格」：可离线查阅 491 个武器、身体护甲、头盔和盾牌条目，包含 94 种红装；支持中英文搜索、类型与品质组合筛选、点击表头排序、双击查看属性详情。436 个条目展示原版图标，其余特殊条目说明原版没有物品图标。查表不需要游戏目录或读取 MOD。普通和传奇装备显示基础值，红装显示抽中词条后的随机范围；详情保留未强化数值与两词条规则，特殊条目说明获取限制。

「装备鉴定」是同一页面的第二个页签，在这里安装或更新读取 MOD，重启游戏，保持 BBMOD 运行即可悬停查看。装备对比使用独立小框，保留游戏原属性框全部内容并自动避让。Ctrl+Alt+D 默认暂停 / 恢复，可直接录入其他快捷键；背景不透明度可调。鉴定结果可以定位到装备表格；后台读取不打断查表。实际游戏悬停与第三方 MOD 组合仍需玩家验收。细节见 [桌面工具说明](docs/desktop-tools.md)。

## 版本管理与自动更新

rc.36 之前的旧版 EXE 请先从 `https://bbmod.com` 手动下载并更换最新版。之后进入「设置」可检查更新、查看进度和调整自动更新；右上角「版本与更新」保留历史版本入口。优先读取官网版本，失败后尝试 GitHub。GitHub 版本记录可能落后于官网。

- 默认开启启动后后台检查；距离上次成功检查不足 6 小时则复用版本记录，软件持续运行时每 6 小时检查一次，也可随时点击「立即检查」。可以关闭自动检查。
- 支持「稳定版」与「稳定版 + 测试版」通道。0.3.0 系列为测试版，默认包含测试版；稳定版通道没有发行版时会明确提示，不会把测试版误报为稳定版。
- 发现较新版本后，右上角显示提示。检查失败、断网或 GitHub 限流不会阻塞主界面，也不会被显示成“已经最新”。
- 主界面更新提示条：发现新版可点击「查看更新」，下载并校验后提示「重启并更新」；「稍后提醒」只在本次运行暂时收起，下载就绪、新版出现或下次启动时再次提示。已有缓存版本也会显示提醒，设置的更新通道继续生效。
- 选择版本可阅读说明、打开发布页面或下载 EXE。下载支持取消，并校验发布资产的大小、SHA-256 和 Windows 程序标识；校验失败不允许安装。
- 默认在后台下载并校验新版，正常退出后静默替换，不重新打开程序。也可主动点击「立即重启更新」。替换失败会尝试恢复旧版，备份保存在 `%APPDATA%/BBMOD/updates/<本次更新目录>/previous.exe.bak`，不再在桌面生成可运行的 `.previous-…exe`。官方带版本号的文件名随升级更新，`BBMOD.exe` 和用户自定义名称保持不变；自动检查、自动下载、退出安装可分别关闭。
- 早期版本留下的 `.previous-…exe` 不会被批量删除；确认主程序内部版本和运行正常后，可退出软件再手动整理。
- 正在刷种子、构建汉化或处理 MOD 时禁止重启更新。设置和下载记录存于 `%APPDATA%/BBMOD`，汉化与 MOD 配置不随 EXE 替换。已有汉化 ZIP 不会被自动重新生成。
- 历史版本可以下载留存；软件不会自动降级。源码运行时可检查和下载，安装按钮仅在 Windows 打包版中启用。无目录写权限时可打开下载目录手动处理。

更新检查使用官网 `/api/v1/desktop/releases/`，并兼容 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases)，不需要登录。发布说明按纯文本展示。重启使用 [PyInstaller 的独立进程环境](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#using-sys-executable-to-spawn-subprocesses-that-outlive-the-application-process-implementing-application-restart)，避免继承已退出程序的解包目录。

## 游戏错误报告

从 BBMOD 启动游戏并保持管理器运行，游戏退出后会检查本次启动产生的日志：出现 error / critical 且之后没有正常关闭记录时，标为“疑似异常退出”，保存日志快照，并在顶部提示可预览提交。启动后很快退出的情况也会在启动等待结束后检查。未变化的旧日志、带正常关闭记录的退出、非 BBMOD 启动和种子远征主动结束不会被收集；进程查询失败不会当作游戏退出。

- 默认只保存到本机，记录位于 `%APPDATA%/BBMOD/crash-reports/`。在「设置 → 游戏错误报告」查看、预览、补充说明并提交；也可开启默认关闭的「自动上传疑似闪退报告」，仅对开启后新收集的报告生效。
- 上传脱敏的错误上下文、MOD 清单和版本，仅管理员可见，不上传存档；上传前隐藏常见路径、邮箱和 IPv4，原始日志快照仅留在本机。
- 日志快照最多保留本次启动新记录末尾 2 MB，上传报告最多 60,000 字，最多保留 20 份记录。
- 断网或网站暂不可用时保留报告，自动上传最多尝试 3 次并遵守网站限流；重启 BBMOD 后沿用同一凭据去重重试。

### 定位问题 MOD

- **可疑 MOD**：报告窗口按报错和调用栈里的脚本路径列出可能相关的 MOD。多个 MOD 带同一文件时，以最后挂载（文件名排序最后）的那份为实际运行的文件，被覆盖的一方也会列出。结果仅供参考：MOD 也可能通过 hooks 改坏原版脚本。
- **上次正常退出（自动）**：从 BBMOD 启动的游戏正常退出后，自动记录当时启用的 MOD 组合，出现在「应用方案」列表中；报告窗口的「恢复上次正常退出时的 MOD 组合」会先预览变更再应用。
- **排查问题 MOD**：「MOD 军械库 → 排查问题 MOD」或报告窗口的「逐步排查问题 MOD」。勾选每轮都保持启用的 MOD（框架和汉化默认勾选），其余参与排查；每轮按提示启动游戏、复现问题、退出后回答。先只保留勾选的 MOD 测一轮：若问题仍在，说明原因不在参与排查的 MOD 中。两个 MOD 只在同时启用时出问题也能找出。所需前置会自动随之启用。排查进度保存在 `bbmod_disabled/bisect.json`，关闭软件后再次打开会继续；可随时「结束并恢复原组合」，排查结束后也可选择恢复原组合并禁用问题 MOD。

检测依据是日志，没有写入错误日志的闪退或 BBMOD 已关闭的情况无法保证检测。「营地总览 → 健康诊断 → 提交错误报告…」手动入口仍可使用。

## 字体与字号

点击左侧最下方「设置」或按 **Alt+8**，选择本机可用的中文字体及 **10–18 号**文字，查看预览后点击「应用字体」。全软件即时生效，重启后保留；「恢复推荐」可重新预览内置 Noto Sans SC 与 12 号文字，再点击应用保存。

默认正文为 12 号（约 16 像素），提示文字、表格行高、表头列宽和标题区域同步调整。较大字号或较小窗口下可滚动查看内容。缺失的系统字体自动回退到内置中文字体。这些设置仅影响 BBMOD 管理器，游戏内文字继续由汉化包提供。配置位于 `%APPDATA%/BBMOD/settings.json` 的 `appearance` 项。

## 官网联动与反馈

Windows 单文件版可在「设置 → 官网联动」注册 `bbmod://`：网页 MOD 链接打开对应作品，由用户决定是否安装；种子链接先预览，再保存到本地收藏。移动 EXE 后需重新启用。诊断报告可在总览或反馈页预览、编辑和导出，仅在主动加入反馈并提交后发送。

## 开发与验证

```powershell
pip install -r requirements-test.txt   # 运行依赖 + pytest；打包另需 requirements-dev.txt
python main.py
python main.py --selftest
python -m pytest tests tools/seedgen_check.py -q
python tools/ui_check.py
python tools/check_localization_manager_ui.py
```

依赖分为三层：`requirements.txt` 只含运行依赖，`requirements-test.txt` 追加 pytest（CI 使用），`requirements-dev.txt` 在测试依赖之上追加 PyInstaller 与 Pillow。

`tests/` 使用临时游戏目录，覆盖独立汉化构建、安装冲突、译文筛选编辑、停止后导出、配置恢复、进程中断恢复、写入失败和备份损坏。
`python -m pytest tests/test_game_detection.py -q` 覆盖无配置首次启动、不可用盘符、Steam 多库、失效的已保存目录及自定义目录的手动选择；不访问实际游戏安装。
`tools/ui_check.py` 以只读方式显示本机游戏状态，生成 1360×880 和 1080×720 的四页截图到 `build/review/`。
`tools/check_localization_manager_ui.py` 使用明确标记的临时示例包，在相同两种尺寸检查汉化管理与编辑页的按钮位置；不会启动游戏或修改本机游戏安装。

桌面完整回归：`python -X utf8 tools/run_desktop_tests.py --all`，各测试模块独立进程运行；Windows CI 执行 MOD 文件管理、恢复、启动、汉化和更新的关键回归。

字体检查：`python tools/check_font_settings_ui.py` 使用隔离配置及隐藏的 Windows Qt 窗口，检查预览、键盘操作、即时应用、真正重启后的保留、字体缺失回退、写入失败恢复与 28 组页面布局；不启动游戏。

node tests/runtime.test.cjs ./build/browser-check/node_modules/jsdom

### 更新器检查

`python -m pytest tests/test_app_updates.py tests/test_update_network.py`；`python tools/check_updates.py --download` 会在临时配置中检查公开版本并下载校验；`python tools/check_update_install.py --exe <新版EXE> --old-exe <旧版EXE>` 只更新隔离的软件副本，运行软件自检，不会打开游戏。

打包前可给安装检查追加 `--source-helper --target-name BBMOD-<版本>.exe`，使用当前源码更新器测试真实 EXE 的版本改名；追加 `--silent` 检查退出更新不重启，也可用带 `.previous-…` 的旧文件名复现历史问题。两种方式均检查程序目录只剩目标 EXE、备份位于缓存、内容校验一致和设置未改变。

### 真实游戏目录工具

以下工具不属于默认隔离测试流程，均需显式指定游戏目录；会修改游戏目录的工具还要求确认参数。运行前关闭游戏并备份 `data`。

- `python tools/scan_check.py --game <游戏目录>`（或 `--data <游戏data目录>`）：只读，对已装 MOD 和本地合集代表包运行静态分析；合集目录可用 `--collection` 指定。
- `python tools/manager_check.py --game <游戏目录> --i-understand-this-modifies-the-game`：在真实 `data` 目录安装、禁用、卸载、快照并恢复测试 MOD，结束时核对与初始状态一致；测试 MOD 来自 `--collection`（默认本地合集），初始文件数用 `--expected-files` 指定。
- `tools/seedgen_check.py`：配置生成与日志解析为离线检查；编排器往返会写入游戏 `data` 后恢复，pytest 下默认跳过，设置 `BBMOD_LIVE_GAME_TESTS=1`（可选 `BBMOD_GAME_DIR=<游戏目录>`）才运行；直接运行时追加 `--i-understand-this-modifies-the-game [--game <游戏目录>]`。
- `python tools/check_afei_seed_live.py --run-game --game "<游戏目录>" --output build/afei-seed-live`：在 Steam 注册的安装目录执行 A/B/A 三轮和两个独立原生战役，比对城镇位置、营地红装实际属性及三名开局人物；退出后校验恢复 MOD 和松散文件。运行前必须关闭已有游戏，不会公开测试种子。

### 本地合集适配

`tools/prepare_fox_collection.py` 校验用户提供的 51 个本地合集原包哈希并输出 52 个独立 ZIP（原包保留），支持组合预检、互斥拦截、预载清单自动合并；`tools/audit_fox_collection.py --lifecycle` 在临时游戏目录执行完整生命周期校验。修复细节与离线验证边界见 [rc.27 说明](releases/0.3.0-rc.27.md) 和 [合集兼容记录](docs/fox-collection-compatibility-20260927.md)。

## 打包

中文地名由普通 MOD 显示，旧注入启动器、DLL、加载代码和构建入口均已从当前实现删除。旧组件的历史检测记录仍保留，参见 [历史排查记录](docs/history/defender-review.md)；新版验证见 [地图记录](localization/MOD_MAP_DISPLAY.md)。

安装 `requirements-dev.txt` 后：

```powershell
python tools/build_icons.py
python -X utf8 tools/build_desktop.py
```

当前 spec 保留单文件构建，成品按 `core/version.py` 中的软件版本命名为 `dist/BBMOD-<版本>.exe`，包含完整独立精修词库、字体、图标、种子脚本和普通 MOD 地图界面代码。打包入口自动执行 `package_check.py` 并记录源码及成品校验清单，拒绝旧注入组件和同版本不同内容的覆盖。编号不随打包次数变化。内置 MOD 资源合集仍从 EXE 周边仓库目录寻找，不把第三方汉化并入应用。

网站发布提供带版本号的主下载文件 `BBMOD-<版本>.exe`。更新器优先读取官网。若另行发布到 GitHub，旧 rc.4／rc.5 更新器仍需要内容完全一致的 `BBMOD.exe` 兼容附件；更新器会校验下载地址、大小和 SHA256。

地名专项检查：先构建预览 ZIP，再运行 `python tools/check_mod_map.py --package <ZIP路径>`。该工具使用离线 Squirrel 解释器、Node.js 和模拟 UI，验证连接、缩放、静止帧复用、离开地图清屏、原名保留与错误恢复；不启动游戏。

打包时将依赖搜索范围限定在 Python 与 Windows 目录，避免其他工具的同名 DLL 混入。`package_check.py` 检查 EXE 内资源，并使用临时用户配置运行桌面自检；不会安装汉化或启动游戏。
