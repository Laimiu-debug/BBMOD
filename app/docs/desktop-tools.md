# 装备百科、软件更新与反馈与建议

rc.20 简化种子码复制：表格工具栏常驻 `copySeedCodes` 按钮，Ctrl+C 复制可见选中行的纯种子码，按表格顺序逐行输出并保留大小写。搜索隐藏行不参与复制，无选择时保留原剪贴板。旧的格式化复制入口改称“复制文案”，保留当前格式和点选复制偏好，快捷键为 Ctrl+Shift+C。复制反馈直接显示在按钮上，选择变化和后台新结果均不主动复制。`tools/check_seed_sharing_ui.py` 用真实 Qt 按钮、键盘事件和剪贴板验证这些操作，并检查小窗口与大字体布局。

rc.19 增加种子批量分享：`core/seedgen/share_queue.py` 只处理用户点击时的本地历史快照，逐条上传并立即持久化回执。已知分享链接不再发请求；不完整记录跳过，临时故障限次重试，网站限流遵守 `Retry-After`，限流时间写入独立状态表并跨停止和重启保留。网络状态码与错误文案保留在队列详情，不再逐条弹窗。用户停止或关闭软件时阻止后续请求，已在发送中的成功回执仍落盘；后续再次点击只上传未成功记录。未展示在表格中的搜索匹配外条目仍在“全部”范围内，回收站和后来发现的种子不在本次范围内。`SeedWorkspaces` 按当前页计算布局，隐藏的生成条件不再撑宽种子库。

验证入口：`tests/test_seed_sharing_queue.py`、`tools/check_seed_sharing_ui.py` 与 `tools/check_font_settings_ui.py`，网络测试使用隔离的本地 HTTP 服务。线上另验证了 2 条真实完整种子的新上传与 6 次重复上传；没有复现原弹窗，不能从“第二次”推断限流根因。

rc.18 调整汉化引导：当前启用状态来自所选游戏目录的实际文件，BBMOD 包同时显示其元数据版本；已保存方案、下拉框选择与待应用切换不等于当前启用状态。导入、收录和制作入口默认收起，制作入口仅导航至编辑页，明确点击制作按钮才会构建。取消待切换选择只回到 `CURRENT`，不调用注册、构建或应用；手动安装但未注册的 BBMOD 包仍识别为已启用。日常使用及仅更新桌面软件不引导重复制作，旧启动组件包才保留换包提示。

rc.17 修正游戏启动反馈：配置已应用时，顶部启动不再跳转汉化页；只在所选方案需要确认或缺失时进入汉化管理。`ui/game_session.py` 异步监测游戏进程，顶部和汉化页共享正在启动、运行中、退出与失败状态，启动请求完成不等于已出现游戏进程。等待期间禁止重复启动，45 秒未检测到进程后提示重试，游戏退出后恢复按钮。游戏运行时不能切换汉化。页面说明统一为新版汉化随游戏加载，Steam 与软件启动均适用。回归入口为 `tests/test_game_launch_ui.py`，截图为 `tools/check_localization_manager_ui.py`；均以隔离目录和受控进程状态验证，不启动真实游戏。

装备百科以软件内的装备资料表为主，默认打开 `装备表格` 页签。内置原版 1.5.2.3 的 491 个装备条目（327 个普通条目、94 种红装、13 个传奇条目及 57 个特殊条目），覆盖武器、身体护甲、头盔、盾牌。没有游戏目录、未安装读取 MOD 或离线时也能查表。支持中英文多词搜索、类型与品质组合筛选、数值排序和双击详情；无结果时可重置筛选。条目含敌方和特殊用途装备，不宣称全部可正常获取。未命名内部条目不进入表格。

普通、传奇及特殊条目显示原始基础数值。红装表格显示抽中强化词条后的范围，详情同时列出未强化值、随机规则和固定属性。红武器 / 盾牌只抽取两组强化，武器耐久另行随机；伤害上下限联动。表格和鉴定共同使用 `core/item_inspector.py` 的离散取整规则。表格不将所有属性满值组合为实际可获得装备，不把随机区间当成实战评分。

`tools/build_equipment_catalog.py` 从本机原版脚本的成员初值与创建字段提取事实，不执行游戏代码，生成 `data/equipment_catalog.json`，记录原始脚本、独立中文词库和红装底材目录的 SHA-256。游戏原始代码、描述文本不随资料表分发。每个红装底材与现有鉴定目录逐字段核对。生成检查和 Qt 查表流程见 `tests/test_equipment_catalog.py`；无游戏目录的两尺寸截图及操作记录由 `tools/check_equipment_catalog_ui.py` 生成到 `build/review/equipment-catalog/`。

2026-09-19 本地检查：304 项回归测试通过、1 项真实进程往返测试按项目默认流程排除；无游戏目录下的搜索、组合筛选、数字排序、详情与空结果流程通过。1360×880 和 1080×720 分别可见至少 9 行和 5 行，28 个字体 / 页面组合检查通过。桌面自检加载 491 条数据；受控日志验证后台读取不覆盖查表状态、鉴定结果准确定位到表格。真实游戏悬停与第三方 MOD 组合验收不包含在这些结果中。

`装备鉴定` 为第二个页签，负责最近一次鉴定结果，以及安装、修复和移除普通 Squirrel MOD `mod_bbmod_item_inspector.zip`。鉴定结果可跳转到装备表的对应条目；后台读取不切换页签或覆盖查表筛选。MOD 操作要求游戏和种子远征均已停止；已有同名未知文件不会被覆盖，旧包保存在游戏目录的 `BBMOD-backups/item-inspector/`。安装时沿用现有脚本框架；没有框架时随包提供已署名的 Modding Script Hooks 21.1。若以后移除提供框架的其他 MOD，请点击修复。

安装或更新到读取 MOD v3 后重启游戏。保持 BBMOD 在后台运行，鼠标移入背包、商店或战利品中的红装，浮层自动显示并跟随鼠标，移开或切出游戏即隐藏。默认 Ctrl+Alt+D 暂停 / 恢复自动提示，可直接录入 Ctrl / Alt 组合或功能键；占用冲突保留原绑定。背景不透明度为 50%–100%，默认 90%，文字不受透明度影响。独占全屏桌面窗口可能不可见，请使用无边框或窗口化。桌面页面保留完整属性表，浮层优先展示抽中的属性。

v3 修复成员代理漏读：游戏中的成员可通过 `WeakTableRef._get` 访问，但 `key in m` 不会调用该代理。旧读取方式因此可能写出空的 `stats`，桌面随后因缺少属性拒绝鉴定。现在逐个尝试读取字段并检查数值类型，护甲附件的原值也使用同一方式；不修改装备、不创建对象、不消耗随机数。离线 Squirrel 成员代理回归与 94 种红装的 9,400 组原版随机数值对照通过。桌面遇到读取错误会清除过期结果并保留错误说明。v2 安装会显示更新提示；正在运行的游戏不会被自动关闭或替换 MOD。

装备表的名称列展示原版物品图标，详情展示较大原图。`tools/build_equipment_icons.py` 静态解析各装备引用的资源与首个外观变体，从原版档案复制图片到 `assets/equipment/`，保留 Overhype Studios 署名、档案路径、图像尺寸及 SHA-256。436 个条目有可用物品图标，含全部 94 种红装；55 个敌方 / 特殊条目未提供物品图标，使用资料占位符并说明原因。打包检查核对全部 740 个去重图片文件。

桌面与任务栏采用多分辨率 `bbmod.ico` 和固定 Windows AppUserModelID。EXE 内嵌图标正常并不意味着桌面已有快捷方式；桌面入口需指向持久保存的 EXE / ICO，不能指向 PyInstaller 临时解包目录。

v2 通过游戏原生 Squirrel/HTML 消息接口关联装备查询与提示框生命周期，查询 token 避免快速切换时串装备；隐藏事件立即收起，400 ms 心跳和 1.2 s 失联超时防止残留。桌面使用只读的前台进程路径与客户区坐标查询过滤非当前游戏，浮层不接收鼠标或键盘焦点。安装时从玩家原版档案读取 tooltip_module.js，保持原内容并追加独立编写的 ES5 适配器，生成到本 MOD 中；不替换 ui/main.html，因此无需捆绑或改动汉化入口。若其他 MOD 直接替换同一 tooltip_module.js，安装会报告冲突并保留原文件；通过框架增加原型 hook 的 MOD 不受这个文件冲突限制。

用户选择保留独立对比小框，自动避开原属性框。MOD 上报原提示框 getBoundingClientRect 与 UI 视口尺寸；桌面按游戏客户区、屏幕原点和当前显示器 DPI 转换坐标，在原框四周的可用区域中选距离鼠标最近的位置，留出 10 个逻辑像素间距。小框宽度随剩余空间调整为 260–360 个逻辑像素；极端情况下没有足够空间，则收起对比框，优先完整显示游戏原属性。没有有效的原框位置时不猜测或覆盖。

`core/item_inspector.py` 对照 `data/item_inspector/catalog.json`。目录由 `tools/build_item_catalog.py` 从原版 1.5.2.3 的技术输入提取 94 个底材的数值，保留源文件和 BBMOD 术语目录哈希；原游戏代码不随目录分发。英文底材名称与随机生成的个体名字分开显示。随机范围保留离散取整、伤害两端联动、武器 / 盾牌两词条规则；护甲使用附件保存的原始数值，超出规则只提供参考范围。没有统一“极品分数”，因为角色技能和用途会改变装备价值。

读取 MOD 包裹实际装备提示函数，复制必要字段到本机游戏日志；不调用随机数、不生成或修改装备、不读取进程内存、不注入 DLL、不写存档。桌面只跟随新增日志，重开应用从日志末尾开始。日志可能包含悬停装备的随机名字；不会上传。

更新源为官网 `/api/v1/desktop/releases/`，失败时尝试原 GitHub 源。更新包须通过 HTTPS 来源、版本文件名、大小和 SHA-256 校验；下载及文件校验使用后台任务。设置页可分别关闭自动检查、自动下载或退出时安装。旧版使用 GitHub 的更新器需要先从官网下载本版一次，之后可以直接通过官网更新。替换仅针对当前软件 EXE；便携文件的原文件名保持不变，以保留现有快捷方式。旁边保留 `*.previous-*.exe` 备份。退出安装不重启，主动安装才重启。

桌面反馈与建议调用 `/api/v1/suggestions/`。GET 提供会话绑定的签名提交凭据和 CSRF token；POST 复用官网表单与提交事务。重试同一内容复用同一个凭据，不重复入库。所有内容在 `/manage/suggestions/` 仅管理员可见；不公开联系方式和内部处理备注。

验证入口：`pytest`、`tools/check_desktop_features_ui.py`、`tests/inspector_harness.nut`、`tests/inspector_hover.test.cjs`、`tools/check_update_install.py`。Qt 流程中的前台游戏身份使用受控 fixture，实际游戏验收仍未完成。`tools/check_inspector_engine.py` 只用于隔离游戏主菜单验证，不进入战役；本机 Steam 隔离启动提前退出，不能作为真实游戏验收通过的证据。

种子远征分为“寻找新开局”和“我的种子”。后者提供搜索、多选删除、回收站恢复和按需展开的分享预览。SQLite 在保留旧表与记录的前提下增加 `deleted_at` 字段；删除保留种子详情、备注与公开分享链接，重新导入只更新记录，不改变删除状态。进行中的远征或分享会阻止删除，避免与新结果或分享回执竞争。删除本地副本不会下架已公开的网页记录。

鉴定界面使用原版游戏的暗色皮革纹理与铁框，原始路径、版本、SHA-256 与署名记录于 `assets/game-ui/sources.json`，版权属于 Overhype Studios。官网种子广场按用户要求保留原有浅色卡片，仅增加分页与每页数量选择。
