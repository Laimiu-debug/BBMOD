## 已确认的实现行为

- `launch_game.cpp` 使用 `CreateProcessW(CREATE_SUSPENDED)` 创建选定的游戏进程，以 `VirtualAllocEx`／`WriteProcessMemory` 写入适配器路径，再通过 `CreateRemoteThread` 调用 `LoadLibraryW`。
- `han_font.cpp` 用 MinHook 适配地图文字的计算和绘制，以及进程内的地名语言标记；原生入口有游戏 EXE 的 SHA256 和调用签名检查。
- 该实现只在显示阶段将英文地名映射成中文。普通游戏启动不设置标记，地图和对话继续使用英文地名。此次没有修改字典、原生渲染和标记协议，也没有切换到英文地名降级版。
- 初始化失败时，旧启动器可能结束它刚创建的游戏进程。以上进程操作确实存在于源码，不能只因为用途是汉化就认定安全产品误报。

原版地图字体使用有限字符表。已有游戏脚本和 UI 接口的只读检查尚不足以证明能完整替代地图渲染适配器；未经游戏验收的替代设计不作为发布版本。

## 本次代码修复

1. 组件缺失或缓存校验失败时给出具体名称、路径和保护历史检查入口，停止后续启动。
2. 对已经初始化的运行缓存只做校验，丢失或改变的可执行文件不自动补回；首次释放中断也不会自动重试。
3. 二进制缓存版本只取决于组件本身。不同地名字典放入独立子目录；检查旧 rc.5 缓存，防止改变字典后重新释放同一组已消失组件。
4. 打包前确认原生文件齐全，缺失即停止；发行 EXE 使用实际版本号命名，并兼容旧更新器附件名称。

这些是错误处理和发布流程修复，**没有改变旧启动器的注入方式，不代表 Defender 检测已解决**。单文件程序自身的资源解包仍由 PyInstaller 完成；运行缓存检查不等于能阻止安全软件在更早的解包阶段拦截程序。

只读生成本地资料：

```powershell
python tools/defender_review.py --exe build/github-release/v0.3.0-rc.5/BBMOD.exe --output build/review/defender-20260917
```

输出包含相关 Defender 记录、发行文件和内置组件的 SHA256、源码摘要校验值，以及可填写的英文说明。脚本只在内存读取发行 EXE 内的组件，不把旧组件解压回磁盘，不启动游戏、不修改防护设置，也不自动上传。资料 JSON 包含本机路径，提交时使用已获授权的发行 EXE 和英文说明。
