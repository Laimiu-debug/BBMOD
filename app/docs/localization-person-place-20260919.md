# 人物属地称号与送货目标修复

独立汉化 **0.3.0-rc.8**，桌面程序 **0.3.0-rc.25**。

用户截图中的“将货物送给索默斯塔德的埃德蒙 的 索默斯塔德，沿路向西行进约一天”，修正为“将货物送给索默斯塔德的埃德蒙，沿路向西行进约一天”。

## 原因和范围

原版 `settlement_faction.onUpdateRoster` 与 `city_state_faction.onUpdateRoster` 会给没有职位的人设置 `of 地名` 称号。`actor.getName` 仍按“姓名＋空格＋称号”拼接；原有介词译文“的 ”无法独立改变顺序。送货委托又将人物完整称呼缓存为 `RecipientName`，并把目的地单独代入 `%objective%的%recipient%`，造成地点重复。

修复在 UI 显示层识别已知姓名、地名与这个明确的称号结构，兼容英文 `of`、已保存的中文 `的` 及混合称呼。只有前文紧邻的完整地点与人物属地相同时才合并，按最长地点识别，避免把“博克霍恩”误当成“霍恩”。普通所有格、未知姓名和内部标识不作全局倒装。

北方姓名、爵士姓名和南方“名＋姓”均使用独立校对的名称表。南方城邦来自另一份原版 `CityStateNames` 数组，本次补入全部 14 个名称的显示索引；不改变原版随机姓名池或城邦生成方式。

除目标模板外，还核对北方送货 `Task` 与南方 `TaskSouthern` 两套对白中同样的组合。已有委托直接使用保存的收件人和目标文本，修复无需重开战役。

## 验证

- 初次修改后 338 项 Python 回归通过；补充城邦识别后，18 项相关回归通过。
- 33,501 个属地称呼用例覆盖姓名与地点的原文、中文组合、重复显示和重复渲染；增加不同地点共享中文后缀的回归。
- 原有 10,222 个称谓形式、128,064 个南方姓名职位组合、12 种战斗结算，以及快速换装提示与 DOM 动态更新检查通过。
- 离线执行实际原版及包内 CNUT 的授衔、姓名拼接、送货收件人缓存、三个委托状态和变量准备。20 条完整目标句经过实际包的 UI 运行时验证，另检查两套对白的所有保留分支。原生变量插值使用明确的测试 fixture，未模拟引擎选择剧情分支。
- 实际委托、基础委托与标签集合的序列化／反序列化方法离线往返通过；关键 ID、收件人缓存及状态保留。
- rc.8 与 rc.7 的 2,286 个脚本文件字节一致，仅姓名显示数据、UI 运行时和包清单变化。EXE 内置资源及项目目录之外的独立自检通过。

**本轮没有启动游戏。** 以上是离线执行和显示检查，真实存档画面尚需实机确认。原版英文资源只作技术输入，没有使用第三方汉化译文或脚本。

本地详细证据保存在 `app/build/review/person-place-20260919/`：Python 测试报告、`dynamic/validation.json`、`native/validation.json`、`native/ui-rendered.json`、`package-diff.json` 和 `package-check.json`。可用 `tools/check_person_place_l10n.py` 与 `tests/person_place_text.test.cjs` 复查最终包。
