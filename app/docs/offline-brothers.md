# 独立人物、地图与红装搜索

桌面 0.9.0 的人物、地图、营地红装及其组合搜索默认使用独立解算器，不要求游戏目录，
也不会启动游戏、切换 MOD 或读取游戏日志。已找到的结果继续进入本地种子库，
可复制、导出和分享到种子广场。可选择游戏解算以兼容旧流程。

支持原版 1.5.2.3、全官方 DLC 的全部 14 种起源，以及战斗、经济、初始资金各三档的 27 种组合。
其中 13 种起源的纯人物搜索保留快速路径：新战团、南方雇佣兵、贸易商队、
农民团、独狼、游侠、圣骑士、掠夺者、解剖学者、猎兽人、角斗士、猎奴人、达库尔信徒。
逃兵的人物创建依赖地图出生点，使用完整独立开局；地图、红装及组合搜索同样执行完整开局规则。
阿飞等自制起源继续使用游戏解算。明确选择「独立解算」时遇到自制起源会在启动前说明。

## 组合搜索先筛人物（0.9.1）

0.9.0 的组合搜索先执行完整地图与营地，最后才判断人物条件，因此人物淘汰率高时明显慢于游戏内的快速人物筛选。
0.9.1 对上述 13 种快速起源先执行同一套人物条件；不合格的种子直接跳过，通过后才完整生成地图、营地与武器。
预筛使用有边界的小批次，保留原种子顺序、命中数和时限停止；命中档案仍由完整开局生成。
人物属性、特质、星位和成长已按 63 组原版起源/难度记录核对一致，避免预筛漏掉本应命中的种子。

人物条件越严格、淘汰越多，收益越明显。人物条件很宽时，大部分种子仍需完整地图解算；逃兵依赖地图出生点，
以及只找地图、只找红装、不使用人物快速生成的模式，继续执行完整路径。独立解算不代表完整地图一定比游戏原生生成更快。

## 地图与红装批量搜索（0.9.0）

- 「只找地图」「只找红装」「地图 + 红装」「人物 + 地图」「人物 + 红装」「人物 + 地图 + 红装」均可独立连续搜索。
- 沿用现有地图/港口、红装数量、词条 roll、实用分和多武器组合条件；选中的各类条件同时满足才保存。
- 按选定起源和难度执行原版人物、物资、玩家落点、势力和营地模拟。每个地图种子使用新的独立进程，避免随机数和对象状态跨轮残留。
- 命中结果继续进入原种子库和分享流程，记录起源、三项档位、版本与 DLC。停止和时限结束保留已完成档案，丢弃未完成的当前候选。
- 从档案打开地图时带入该档案的完整开局配置；不同配置分别缓存。没有完整配置的旧档案和自制起源不会被默认为民兵红装。
- 完整地图/营地解算需要执行地形与势力模拟，速度远低于纯人物筛选；界面显示当前阶段和实际种子/秒。

完整独立开局执行原版人物、背景、装备、起源和势力脚本，仅提供无界面的原生服务。
人物描述中的文本变体使用与游戏一致的另一条随机数流，避免改变后续的天赋、出生点和红装。
组合筛选的规则包由现有游戏搜索脚本生成，包含地图统计、环线路线、红装 roll 与武器条件，不另写近似判定。

完整对照工具：`tools/validate_campaign_search.py`。原版采样分小批次运行，结束后恢复原 MOD 文件并核对哈希；正常独立搜索不调用采样器。

## 筛选行为

- 属性、必选与排除特质、总星数、各属性星位由同一名兄弟同时满足，再统计不同兄弟的人数。
- 星位支持 0–3 星的范围和精确值，包括指定零星；保留特质全部具备、任一具备两种规则及原有别名。
- 保留起源预设、职业评分、队伍评分与职业人数分配。
- 支持逐级模拟真实成长与按星级平均成长；真实成长按原版预先生成的升级表计算。
- 保留区分大小写的种子、三个难度档位、全 DLC 标记及空 MOD 环境，沿用已有分享格式。
- 搜索显示轮数、命中数、速度与耗时，支持按命中数或时限自动停止，取消时回收独立进程并保存已完成结果。

## 实现与验证

独立宿主仍使用固定的 Squirrel 3.1、32 位整数及浮点语义和原版随机数规则。
`tools/prepare_brother_rules.py` 从共享的生成人物、评分与筛选代码组装独立规则，
没有另写一套 Python 随机数或近似星位算法。人物分支在创建地形前进入，单个进程持续搜索多个种子。
临时任务配置在本机 H 盘；普通用户机器使用系统临时目录。部署后的运行过程不读取游戏安装。

本次同时修正旧快速代码的箭袋创建、游侠换装、猎兽人猎犬与开局物品、
角斗士描述与固有特质、解剖学者新增药剂，以及新版描述导致的 11 级成长随机数对齐。

原版采集只用于开发校验，生成实际原版人物并读取基础属性、特质、天赋与十级升级表。
采集按小批次运行，避免原游戏在一次进程中重复创建过多战役和人物造成资源累积。
所有用于验收的采集均完成且通过游戏目录恢复 SHA 校验。
7 个种子、13 个起源，共 91 组组合、343 名人物的上述四项数据全部零差异。
参考原件保存在 `build/offline-map/brothers-reference-second` 与 `brothers-reference-extra`；
回归夹具为 `tests/fixtures/worldmap/brothers.json.gz`。

本机实测开启真实 11 级成长，每起源搜索 1,000 个种子：农民团约 300 种子/秒，
独狼约 3,800 种子/秒；不同起源人数与系统负载会影响速度。测量使用低命中率的特质及星位组合，
不包含大量结果落库的额外耗时。完整记录在 `build/offline-map/brother-benchmark.json`。

```powershell
py -3.13 -X utf8 tools/prepare_brother_rules.py
py -3.13 -X utf8 tools/validate_brothers.py --reference build/offline-map/brothers-reference-second/reference.jsonl --reference build/offline-map/brothers-reference-extra/reference.jsonl --fixture tests/fixtures/worldmap/brothers.json.gz
py -3.13 -X utf8 tools/benchmark_brothers.py --count 1000
```

地图、营地、人物各自的原版对照报告必须与当前组件指纹一致，才允许打包。
成品自检会实际运行内置的人物解算并检查 12 名农民团兄弟，而不只检查文件是否存在。

## 0.8.1 输出、保存与回收优化

人物结果使用宿主的原生 JSON 编码，保持旧协议的字符串处理、六位有效数字及完整档案行。
生成人物、原版随机数、11级成长、评分和命中判定继续使用原有规则。
后台读取器将连续命中合并为短批次，再等待界面确认保存；队列与单次合并均有边界。
种子库按最多500个身份批量读取历史，在一个事务内合并并写入；批内重复、完整度优先、
历史顺序、分享链接和回收站标记保持原有行为，SQL失败会回滚整批。
人物背景继承绑定完成后释放临时递归闭包，避免每个人物都留下只能等待循环回收的对象。

固定输入对照覆盖13起源、真实/平均成长、大小写种子及连续随机搜索，共52组、3,614次解算。
其中1,014条返回完整原始人物、属性、天赋、成长增量和评分条目；全部档案行和命中结果逐条相等。
另外，相同10,000个独狼种子及1,000个农民团种子分别进行三轮交替测速，核对每条落库记录的完整内容，
未改动用户历史，也未启动游戏。全部命中时，独狼桌面中位速度899→1,431种子/秒，农民团229→276种子/秒；
严格条件下的低命中率速度基本不变。原始结果在 `build/offline-map/optimization-20261022`。
无命中记录留存的10,000个农民团种子持续搜索测试中，优化后的解算进程工作集稳定约15 MB；
旧版随搜索逐步增长到约41 MB。该数值只统计后台解算进程，不包括桌面界面和需要保留的命中历史。

```powershell
py -3.13 -X utf8 tools/check_brother_optimization.py --snapshot build/offline-map/optimization-20261022/results-after.json.gz --compare build/offline-map/optimization-20261022/results-before.json.gz --report build/offline-map/optimization-20261022/equivalence.json
py -3.13 -X utf8 tools/benchmark_brother_pipeline.py --count 10000 --repeats 3 --baseline build/offline-map/optimization-20261022/before --output build/offline-map/optimization-20261022/pipeline-lone-wolf.json
py -3.13 -X utf8 tools/benchmark_brother_pipeline.py --origin scenario.militia --count 10000 --memory --baseline build/offline-map/optimization-20261022/before --output build/offline-map/optimization-20261022/memory.json
```
