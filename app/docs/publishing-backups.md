# 发布备份与服务器存储约定

用户于 **2026-10-06** 明确要求：**不要默认做完整备份，不要重复备份历史桌面 EXE。**
本约定适用于 BBMOD 官网发布与服务器维护，后续执行以此为准。

## 常规桌面发布

1. 校验待发布 EXE 的版本、大小、SHA-256 和既有测试结果。
2. 使用 SQLite 在线备份接口，仅保存必要的数据库一致快照；另记录本次涉及的发布 ID、版本、状态、文件路径及校验信息。
3. 以新版本导入和公开文件，不覆盖已发布的同版本文件。既有下载原件继续由官网使用，不再为本次发布复制历史 EXE。
4. 验证推荐版本、下载文件名、大小、完整哈希及客户端检查更新。
5. 验收完成后，清理本次任务产生的上传临时 EXE、传输基底、差分包和容器临时副本。保留正式下载存储中的原件与小体积发布、验收记录。

官网正式下载文件与临时文件必须核对实际路径和网站引用关系，不能因清理临时文件误删正式下载原件。

## 网站维护

仅备份本次即将修改的数据库、配置或代码；不可因为小范围更新而复制全部 MOD、历史 EXE、百科图片或整个持久卷。

`backup_hub` 会生成全站完整备份，**常规发布和维护不得默认调用**。只有用户明确要求完整备份时才执行；不默认创建整站备份定时任务。

凭据、私钥和账号秘密继续按既有受限路径管理，不进入发布记录、日志或仓库。

## 历史记录

0.4.0 发布时生成的约 2.67 GB 完整备份是已发生的历史操作，范围过大，后续不得沿用该流程。
历史发布记录中的完整备份命令和旧脚本不代表当前用户授权，也不能直接作为新发布模板。
