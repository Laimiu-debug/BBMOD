# 固定版本与打包规则

从桌面 **0.3.1** 起，公开版固定使用 `主版本.功能版本.修复版本`：

- 修复缺陷、调整性能和兼容性：末位递增，例如 `0.3.1 → 0.3.2`。
- 增加一组功能：中间位递增、末位归零，例如 `0.3.2 → 0.4.0`。
- 不兼容的大改版：主版本递增，例如 `0.4.0 → 1.0.0`。
- 只修改测试、文档或重复执行打包：不改版本号。

不再根据当天日期、构建次数或任务名称改变编号方式，不继续递增历史的 `rc.38`。
旧 rc 版本继续保留在更新历史中；当前更新器按语义版本比较，可从 rc.38 升级至 0.3.1。
只有用户明确要求新的预发布系列时才另行讨论预发布渠道。

版本唯一来源是 `core/version.py` 的 `VERSION`。界面、Windows 版本资源、
打包文件名、版本说明和网站发布记录使用同一值。成品固定为 `BBMOD-<版本>.exe`，
不添加日期或随机后缀；公开过的同一版本不得替换成不同内容。

使用 `python -X utf8 tools/build_desktop.py`。该入口不自动修改版本，执行单文件构建
和隔离成品自检，记录源码及成品 SHA-256。重复构建相同版本、相同源码会复用已验证
成品；源码发生变化时拒绝覆盖同版本成品，需在实际发布时明确递增版本。

内部测试日志、打包缓存和部署时间可以记录日期，它们不成为软件版本号。
独立汉化只在汉化内容变化时升级，当前仍为 `0.3.0-rc.9`；网站保持独立三段版本，
服务器代码变化按网站自己的修复版本升级，发布桌面 EXE 不连带改变网站编号。

## 发布备份范围

发布前遵守[备份与存储约定](publishing-backups.md)。用户明确要求默认不做完整备份，
不重复备份历史桌面 EXE；常规桌面发布仅保留必要的数据库一致快照、发布记录和校验信息。
`backup_hub` 不作为常规发布步骤。完整备份仅在用户明确要求时执行。
