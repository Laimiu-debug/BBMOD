# 0.3.0-rc.33

- 从 BBMOD 启动游戏并保持管理器运行，退出后检查本次启动产生的日志。发现 error / critical 且之后没有正常关闭记录时，标为“疑似异常退出”，保存日志快照并显示提交入口。启动后很快退出、未赶上进程检测的情况也会在启动等待结束后检查。
- 默认只保存到本机。在“设置 → 游戏错误报告”查看、预览、补充说明并提交；也可以开启“自动上传疑似闪退报告”。开关默认关闭、立即保存，仅对开启后新收集的报告启用自动上传，关闭后停止后续自动提交。
- 上传脱敏的错误上下文、MOD 清单和版本，仅管理员可见，不上传存档。不会覆盖“反馈与建议”中正在编辑的草稿。
- 日志快照最多保留本次启动的新记录末尾 2 MB；上传的是最多 60,000 字的文本报告。再次启动游戏不会覆盖已保存的快照。最多保留 20 份记录，满额时先清理最早的已送达报告，未发送记录需手动删除。
- 断网或网站暂不可用时保留报告，自动上传总共最多尝试 3 次；遵守网站限流等待时间。重启 BBMOD 后保留原提交内容、凭据与会话，用于去重重试。凭据过期且发送结果不确定时暂停自动提交，提示核对，避免自动换凭据重复入库。
- 排除未变化的旧日志、带正常关闭记录的退出、非 BBMOD 启动和种子远征主动结束；进程查询失败不会当作游戏退出。
- 修复退出管理器时恰逢后台进程查询而被“任务处理中”弹窗拦住的问题，关闭时会等待该查询结束。

本地记录位于 `%APPDATA%/BBMOD/crash-reports/`，可从报告窗口打开。原始日志快照仅留在本机，可能包含本地路径；上传前按现有规则隐藏常见路径、邮箱和 IPv4。

检测依据是日志，不能保证识别所有闪退；没有写入错误日志或 BBMOD 已关闭的情况不会自动收集。此次更新无需重新生成独立汉化包。测试使用隔离日志和本地模拟服务，未主动让真实游戏崩溃。
