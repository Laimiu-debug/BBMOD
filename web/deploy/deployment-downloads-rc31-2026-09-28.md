# 下载超时修复 rc.31 · 2026-09-28

按用户优先处理下载超时、尤其汉化包下载的要求，官网已启用文件网关传输及直连下载，并于 **2026-09-28 16:00（UTC+8）**发布管理器 **0.3.0-rc.31**。独立汉化内容仍为 rc.9，ZIP 未重新生成或替换。

## 排查证据

- 原汉化下载接口忽略 `Range`，请求 1 MB 分段仍返回 `200` 和完整的 34,531,946 字节文件。下载由 Django `FileResponse` 持续占用应用线程；应用只有 4 个请求线程。
- 桌面在线军械库存在 12 秒连接 / 读取超时和固定 180 秒总下载时限，连接中断后直接删除临时文件，没有重试或续传。
- 实测同一汉化包的官网转发请求出现 20 秒零字节超时，直连 `https://gongpro.cn/bbmod-origin` 的 1 MB Range 请求则返回 `206`，耗时 0.99 秒。服务器向官网请求小型 API 也出现过超时；单纯增加文件总时限不能解决转发入口不稳定。
- 正常网络时旧线路也能完成整包下载，不能据此将所有超时归因于服务器负载，亦未将 Vercel 首字节等待时间误判为整个下载的固定时限。

## 修复

- MOD、汉化与共享文件仍先由 Django 检查公开 / 下架 / 作者状态、文件路径和大小，再用 `X-Accel-Redirect` 交给 Nginx 私有目录传输。支持 HEAD 和 Range；外部不能直接访问 `/_mods/`。数据卷在网关中只读挂载。
- 网页 MOD 详情和软件下载按钮使用现有 HTTPS 直连源站，同样执行权限检查。旧链接和 API 相对路径保持兼容。可用 `BBMOD_PUBLIC_DOWNLOAD_BASE` 配置，未配置时沿用站内路径。
- 软件取消正常传输的 3 分钟硬性截断；单次无响应等待 20 秒，最多重试 4 次。在本次下载中保留已收到的字节，并严格检查续传起点、终点、总大小和最终 SHA-256。服务器忽略 Range 时清空临时内容重新开始，避免拼接损坏。
- 官网公开 MOD / 方案下载连接失败后切换同一服务器的固定 HTTPS 直连路径。自定义源、带查询参数或非公开路径不会切换；404 等非暂时错误不回退，避免绕过下架状态。
- 在线军械库显示下载大小、百分比及重试状态。共享方案文件也采用相同的重试和续传逻辑。
