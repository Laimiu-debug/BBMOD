# 反馈处理与回复

## 管理员

进入 `/manage/suggestions/`，按「尚未回复」、处理状态或错误关键词筛选，打开反馈详情。

- 「给用户的回复」用于写明排查步骤、修复版本或需要用户补充的内容。填写后点击「保存处理记录与回复」发布；每次回复作为独立记录保留，按时间显示。
- 「内部备注」继续只在后台显示，不会转成用户回复。回复留空时，只更新状态及内部备注。
- 状态和回复在同一个数据库事务中保存。重复提交或过期编辑返回冲突提示，不会重复发布，也不会覆盖其他管理员的新记录。保存失败保留当前填写内容。
- 发布前检查回复中的个人信息。持有回执编号的人均能看到回复和处理状态。后台「查看用户页面」可核对实际可见内容。

## 用户

在「反馈与建议」选择「查看处理进度与回复」，输入提交成功后得到的 12 位回执编号，无需账号。旧版本提交的回执也适用。

提交成功页提供直接查询链接；桌面提交 API 继续返回原有 `schema_version` 和 `reference`，另增加站内 `reply_url`。旧客户端无需升级即可继续提交，用户手动输入回执查询。网站不向桌面弹出提醒，也不通过邮件或 QQ 发送消息。

查询页只显示管理员主动发布的回复和处理状态，不提供原始标题、正文、日志、联系方式或内部备注。没有回复时明确提示等待回复；状态变为「已完成」不会自动产生回复。

同一浏览器用签名、HttpOnly、SameSite=Lax Cookie 保存最近 30 条回执，保留一年。清理 Cookie、换设备或旧版本没有留下该 Cookie 时，需要手动输入原回执。回执编号和链接应自行保管，网站不提供公开反馈列表或通过称呼搜索的功能。

## 部署与验证

新增迁移 `0011_suggestion_replies` 只创建回复表，不修改原反馈。升级执行正常的 `python manage.py migrate --noinput`。回退到前一代码镜像时保留新增表及其数据，不回灌旧数据库，也不删除已保存回复。

查询接口独立限流：每个受信任来源地址每小时最多 120 次、全站最多 3,000 次。限流只保存按小时生成的 HMAC 摘要，不保存原始地址；查询不占用提交反馈的额度。页面禁用缓存和搜索索引，引用策略仅传递来源站点，避免回执路径进入引用来源。

验证命令：

```text
python manage.py test catalog.test_suggestion_replies catalog.test_suggestions --noinput
python manage.py makemigrations --check --dry-run
```

回归覆盖管理员权限、CSRF、旧回执兼容、原文隐私隔离、HTML 转义、按时间显示、重复提交与过期编辑冲突、数据库失败回滚、独立查询限流、Cookie 防篡改及回复筛选分页。正式部署前还需用浏览器验证「保存回复 → 回执查询」，并遵守 `app/docs/publishing-backups.md` 的最小备份范围。
