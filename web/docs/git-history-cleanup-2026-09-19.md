## 平台残留边界

匿名 GitHub API 检查：新提交根目录没有 `其他mod`，但旧提交仍返回包含该目录的对象。分支、标签的可达历史清理已经完成，不能宣称 GitHub 已物理清除旧对象。

[GitHub 官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)指出，强推后旧提交仍可能通过哈希缓存、其他克隆或 fork 访问。官方敏感信息清理支持不承诺处理非敏感内容，因此本记录不承诺提交普通清理工单就能消除版权相关残留。没有擅自删除仓库、改变公开性或向第三方发消息。

本地旧备份和 Codex 内部历史引用同样可能包含旧收藏，保留用于恢复，不应公开上传或使用 `git push --mirror` 推送。

## 其他电脑如何同步

有未提交修改时，先在本机保存补丁或提交备份。没有本地修改的其他克隆，重新克隆仓库最稳妥；不要把旧 main 合并回新 main，以免把旧收藏历史重新带回公开仓库。

如果需要恢复，完整 bundle 与增量 bundle 都在上述本地输出目录。恢复操作应在新的隔离目录进行，不把旧历史直接推回官网仓库。
